## AI Orchestration

Project VXにおけるバーチャル開発者は、一つのAIモデルがすべてを行う仕組みではありません。企画、現在の開発状態、利用可能なTool、作業のRisk、過去の検証結果を確認し、その時点で必要な担当やToolへ作業を分配する Orchestrator として考えています。

ルミ、Coding Agent、複数のAIモデル、Unity、Git、Reviewをつなぎ、必要な仕事を必要な場所へ渡す。その接続全体を、開発環境の一部として扱います。

## Harnessing

Harnessingは、AIへ答えだけを渡すのではなく、AIがより正しい仕事へ近づくための環境そのものを設計する考え方です。

作業前に確認する情報、企画と開発状態の優先順位、検証方法、再試行や停止の条件、Gitの扱いまでを含めて定義します。AIの失敗を個別の失敗で終わらせず、なぜ現在の環境では防げなかったのかまで遡って改善することを目指します。

## Model Routing

すべての作業に同じモデルや同じ推論量が必要とは限りません。作業の難易度、不確実性、影響範囲、必要な検証強度に応じて、必要十分な能力を選ぶことも Project VX の設計対象です。

## AI Orchestration

Project VX에서 버추얼 개발자는 하나의 AI 모델이 모든 일을 하는 구조가 아닙니다. 기획, 현재 개발 상태, 사용할 수 있는 Tool, 작업의 Risk, 과거 검증 결과를 확인하고, 그 시점에 필요한 담당과 Tool에 작업을 배분하는 Orchestrator로 생각합니다.

루미, Coding Agent, 여러 AI 모델, Unity, Git, Review를 연결하고, 필요한 일을 필요한 곳으로 전달합니다. 이 연결 전체를 개발 환경의 일부로 다룹니다.

## Harnessing

Harnessing은 AI에게 답만 주는 것이 아니라, AI가 더 올바른 작업으로 다가갈 수 있도록 작업 환경 자체를 설계하는 사고방식입니다.

작업 전에 확인할 정보, 기획과 개발 상태의 우선순위, 검증 방법, 재시도와 중단 조건, Git 사용 방식까지 포함해 정의합니다. AI의 실패를 개별 실패로 끝내지 않고, 왜 현재 환경에서 막지 못했는지까지 거슬러 개선하는 것을 목표로 합니다.

## Model Routing

모든 작업에 같은 모델이나 같은 수준의 추론이 필요한 것은 아닙니다. 작업 난이도, 불확실성, 영향 범위, 필요한 검증 강도에 따라 필요충분한 역량을 선택하는 일도 Project VX의 설계 대상입니다.
