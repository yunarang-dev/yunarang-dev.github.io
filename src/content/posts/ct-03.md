**담당 역할:** HP UI 및 HUD 개선

<br>

1주차에는 플레이어가 현재 Heat와 장착 중인 Core를 확인할 수 있도록 HUD의 기본 구조를 만들고, 각 시스템의 변경 이벤트를 UI와 연결했다.

2주차에는 여기서 한 단계 더 나아가, 기존 Heat·Core HUD와 통일된 형태로 HP UI를 확장하는 작업을 맡았다.

<br>

이번 주의 목표는 단순히 체력 수치와 게이지를 화면에 표시하는 것만이 아니었다. 플레이어가 피해를 입었을 때, 또는 위험한 상태에 진입했을 때 숫자를 직접 읽지 않더라도 상황을 직관적으로 인식할 수 있도록 **시각적인 피드백을 추가하는 것** 이 목표였다.

사망 또는 게임오버 UI는 관련 에셋이 아직 제작 중이었기 때문에 이번 주에는 추가하지 않고, 후속 작업으로 남겨두었다.

## 기존 HUD 구조 정리와 Core 아이콘 연동

HP UI를 추가하기에 앞서, 먼저 1주차에 제작했던 HUD의 계층 구조를 정리했다.

<br>

1주차 당시 현재 Core UI는 `CoreData`에서 Core 이름을 받아 텍스트로 표시하는 수준이었다. 하지만 전투 중에는 텍스트보다 이미지가 훨씬 빠르게 인식되기 때문에, 2주차에는 현재 장착 중인 Core를 보다 직관적으로 확인할 수 있도록 `CoreData`에 UI용 아이콘을 추가했다.

```csharp
[Header("Identity")]
[SerializeField] private string coreName;
[SerializeField] private Sprite coreIcon;

public string CoreName => coreName;
public Sprite CoreIcon => coreIcon;
```

각 Core의 ScriptableObject 데이터에 `Sprite`를 지정할 수 있도록 `coreIcon` 필드를 추가했다.

<br>

그리고 `CoreDrawer`에서는 기존처럼 이름만 표시하는 것이 아니라, 현재 Core에 지정된 아이콘까지 함께 받아 표시하도록 수정했다.

```csharp
public void SetCore(CoreData coreData)
{
    if (coreData == null)
    {
        coreText.text = "None";
        coreImage.sprite = null;
        return;
    }

    coreText.text = coreData.CoreName;
    coreImage.sprite = coreData.CoreIcon;
}
```

정상적인 `CoreData`가 전달되면 Core의 이름과 아이콘을 함께 표시한다.

반대로 Core 데이터가 존재하지 않는 경우에는 텍스트에 `None`을 표시하고, 이전에 사용하던 Core 아이콘이 그대로 화면에 남지 않도록 `Sprite`를 비워두었다.

<br>

이 작업을 통해 Core UI는 임시 텍스트 위주의 표시에서 벗어나, 실제 아이콘을 사용할 수 있는 구조로 확장되었다.

또한 UI 테스트 폴더에 임시로 들어 있던 Core 이미지들을 공용 아트 리소스 폴더로 옮기고, 각 Core 데이터에 사용할 아이콘을 지정했다.

HP UI를 새롭게 추가하기 전에, 기존 HUD의 구조와 리소스부터 먼저 정리한 셈이다.

<br>

**[이미지 1 삽입 — Core 아이콘이 적용된 HUD]**

<br>

## 기존 Heat·Core HUD와 통일된 HP UI 구성

HP UI는 기존 Heat·Core UI와 동일한 HUD 안에 배치했다.

<br>

HP 영역은 다음과 같이 구성했다.

* `HPFrame`: HP 바의 배경 및 외곽 프레임
* `HPFill`: 현재 HP 비율에 따라 줄어드는 이미지
* `HPText`: 현재 HP와 최대 HP를 표시하는 텍스트
* `HPParticle`: HP가 감소했을 때 재생되는 파티클

<br>

HP 데이터는 `HPDrawer.SetHP()`를 통해 화면에 반영하도록 만들었다.

```csharp
public void SetHP(int current, int max)
{
    if (max <= 0)
        return;

    float fill = (float)current / max;

    hpFill.fillAmount = fill;

    if (hpText != null)
        hpText.text = $"{current}/{max}";

    previousHP = current;
}
```

현재 HP를 최대 HP로 나누어 `0~1` 사이의 비율로 변환한 뒤, 해당 값을 `hpFill.fillAmount`에 전달했다.

<br>

예를 들어 현재 HP가 75이고 최대 HP가 100이라면 다음과 같이 표시된다.

* HP 바 채움 비율: `0.75`
* HP 텍스트: `75/100`

<br>

이렇게 현재 수치와 최대 수치를 함께 표시함으로써, 플레이어는 남은 체력의 비율뿐 아니라 정확한 수치도 동시에 확인할 수 있도록 했다.

## HP 시스템이 완성되기 전에 VFX부터 만들기

HP 감소 파티클을 제작하기 시작했을 당시에는 실제 플레이어 HP 시스템이 아직 프로젝트에 추가되지 않은 상태였다.

따라서 처음부터 실제 전투에서 HP가 감소했을 때 파티클이 재생되도록 연결할 수는 없었다.

<br>

그렇다고 HP 시스템이 완성될 때까지 UI 작업을 멈출 필요는 없다고 생각했다.

그래서 우선 파티클의 모양과 위치, 재생 방식 등 **독립적으로 구현할 수 있는 시각 요소부터 먼저 제작** 하고, Unity Inspector에서 직접 확인할 수 있도록 구성했다.

<br>

당시 팀 디스코드에도 다음과 같이 현재 상황을 공유했다.

> 추가로 아직 플레이어 HP 관련 부분이 구현되지 않은 듯해서 UI와 연결은 안 해둔 상태입니다. Inspector에서 Particle 설정의 Play on Awake 설정이랑 Looping 설정을 켜면 대략적으로 어떻게 나타나는지 보실 수 있습니다.

<br>

이 단계에서는 파티클의 동작을 확인하기 위해 `Play on Awake`를 사용했다.

파티클을 자동으로 반복 재생하도록 설정하면, 실제 HP 이벤트가 존재하지 않더라도 화면에서 파티클의 위치와 형태를 먼저 확인할 수 있었다.

<br>

이후 실제 HP 시스템과 연결한 뒤에는 파티클이 씬 시작과 동시에 재생되지 않도록 `Play on Awake`를 끄고, 반복 재생을 방지하기 위해 `Looping` 역시 비활성화했다.

최종적으로는 **HP가 실제로 감소하는 순간에만 코드에서 `Play()`를 호출하는 구조** 로 정리했다.

다른 시스템의 구현을 기다리면서 작업을 멈추기보다, 먼저 독립적으로 제작할 수 있는 부분을 준비하고 나중에 연결하는 방식으로 개발을 진행한 것이다.

## HP가 감소했을 때만 파티클 재생하기

단순히 HP UI가 갱신될 때마다 파티클을 재생하면 문제가 생긴다.

씬이 시작되면서 초기 HP를 표시하거나, 플레이어가 HP를 회복하는 상황에서도 피해를 입은 것처럼 파티클이 재생될 수 있기 때문이다.

<br>

이를 방지하기 위해 이전 HP 값을 저장해 두고, 새로운 HP가 이전 값보다 작아졌을 때만 파티클을 재생하도록 만들었다.

```csharp
private int previousHP = -1;

public void SetHP(int current, int max)
{
    if (max <= 0)
        return;

    float fill = (float)current / max;

    if (previousHP != -1 &&
        current < previousHP &&
        hpParticle != null)
    {
        MoveParticle(fill);
        hpParticle.Play();
    }

    hpFill.fillAmount = fill;

    if (hpText != null)
        hpText.text = $"{current}/{max}";

    previousHP = current;
}
```

`previousHP`의 초기값은 `-1`로 설정했다.

처음 UI를 초기화할 때에는 비교할 이전 HP가 존재하지 않기 때문에, 이때는 파티클을 재생하지 않는다.

<br>

두 번째 갱신부터는 다음 세 가지 조건을 확인한다.

* 이전 HP 값이 존재하는가
* 현재 HP가 이전 HP보다 감소했는가
* 사용할 파티클 시스템이 연결되어 있는가

<br>

세 조건을 모두 만족했을 때만 HP 감소 파티클을 재생한다.

덕분에 상황에 따라 다음과 같이 동작하도록 만들 수 있었다.

* 씬 시작 시 최대 HP 표시 → 파티클 재생 안 함
* HP 회복 → 파티클 재생 안 함
* 같은 HP 값으로 다시 갱신 → 파티클 재생 안 함
* 피해를 받아 HP 감소 → 파티클 재생

<br>

단순히 `SetHP()`가 호출되었는지를 기준으로 판단하는 것이 아니라, **실제로 HP가 감소했는지를 비교하여 피해 효과가 필요한 순간을 구분** 한 것이다.

## 감소한 HP 바의 끝으로 파티클 이동하기

HP 감소 파티클은 HP 바의 고정된 위치에서 재생되는 대신, HP가 감소한 뒤 남아 있는 Fill의 끝부분에서 재생되도록 만들었다.

플레이어가 피해를 받으면 HP 바가 줄어들고, 그 줄어든 경계에서 파티클이 발생하는 방식이다.

```csharp
private void MoveParticle(float fill)
{
    RectTransform rt = hpFill.rectTransform;

    float x = rt.rect.xMin + rt.rect.width * fill;

    Vector3 worldPos =
        rt.TransformPoint(new Vector3(x, 0, 0));

    hpParticle.transform.position = worldPos;
}
```

먼저 `HPFill` 이미지의 `RectTransform`을 가져온다.

그다음 HP의 현재 비율을 이용해, 이미지 내부에서 Fill이 끝나는 X좌표를 계산한다.

<br>

계산 방식은 다음과 같다.

**HP Fill의 왼쪽 좌표 + (HP Fill 전체 너비 × 현재 HP 비율) = 현재 HP 바가 끝나는 위치**

<br>

해당 위치는 UI 오브젝트의 로컬 좌표이므로, `TransformPoint()`를 이용해 월드 좌표로 변환한 뒤 파티클의 위치에 적용했다.

예를 들어 HP가 100%라면 파티클은 HP 바의 오른쪽 끝에 가깝게 위치하고, HP가 30%라면 왼쪽에서 30% 지점으로 이동한다.

<br>

**[이미지 2 삽입 — HP 감소 시 Fill의 끝에서 재생되는 파티클]**

<br>

> HP가 감소하면 남아 있는 HP Fill의 끝으로 파티클을 이동시킨 뒤 재생한다. HP 바가 줄어드는 위치와 피해 효과가 일치하도록 구성했다.

<br>

단순히 숫자와 게이지만 변화시키는 것보다, **HP가 실제로 잘려나가는 위치에 시각 효과를 배치함으로써 피해를 보다 직접적으로 느낄 수 있도록** 만들고자 했다.

## 파티클을 UI 위에 표시하기 위한 Canvas 설정 변경

HP 감소 파티클은 Unity의 `ParticleSystem`을 사용해 제작했다.

그런데 기존 Canvas는 `Screen Space - Overlay` 방식으로 렌더링되고 있었다.

Overlay 방식의 Canvas는 일반적인 월드 공간의 파티클보다 앞에 그려지기 때문에, 파티클이 UI 뒤에 가려지거나 원하는 순서대로 표시되지 않는 문제가 발생할 수 있었다.

<br>

이를 해결하기 위해 Canvas의 Render Mode를 다음과 같이 변경했다.

* 변경 전: `Screen Space - Overlay`
* 변경 후: `Screen Space - Camera`
* Render Camera: `Main Camera`
* Plane Distance: `1`

<br>

Canvas가 Main Camera를 기준으로 렌더링되도록 변경한 뒤, 파티클의 Sorting Order를 조정하여 HP UI 위에 정상적으로 표시할 수 있도록 했다.

이 변경은 코드가 아니라 Unity 씬과 Canvas 설정에 직접 저장되는 값이었다.

따라서 다른 팀원이 동일한 Canvas를 수정한 뒤 병합할 경우, Render Mode나 Render Camera 참조에서 충돌이 발생할 가능성이 있었다.

<br>

이 때문에 작업 직후 팀 디스코드에 다음과 같이 변경 내용을 공유했다.

> HP Particle을 구현하는 과정에서 Canvas의 Render Mode를 Canvas(Screen Space - Overlay)에서 Canvas(Screen Space - Camera)로 변경했습니다. Main Camera를 Render Camera로 지정해서 사용 중입니다. 이로 인해 Merge하는 과정에서 Canvas 쪽에서 Render Mode 관련 충돌이 일어날 수 있으니 참고 부탁드립니다.

<br>

단순히 변경 내용을 커밋하는 데서 끝내지 않고, 다른 팀원이 병합할 때 확인해야 할 Unity 씬 설정까지 함께 공유했다.

Unity의 씬이나 프리팹은 코드처럼 변경 내용을 한눈에 파악하기 어려운 경우가 많다.

특히 Canvas의 Camera 참조처럼 씬 오브젝트와 직접 연결되는 설정은 병합 과정에서 참조가 사라지거나 다른 값으로 변경될 수 있기 때문에, 따로 확인할 필요가 있었다.

<br>

**[이미지 3 삽입 — Canvas의 Screen Space - Camera 설정]**

<br>

> UI 파티클을 정상적으로 렌더링하기 위해 Canvas를 Screen Space - Camera 방식으로 변경하고 Main Camera를 연결했다.

## PlayerHealth 시스템과 HP UI 연결

HP 감소 VFX를 처음 구현했던 7월 20일 오전 1시경에는 플레이어 HP 시스템이 아직 프로젝트에 존재하지 않았다.

그러나 같은 날 이후, 팀원이 다음 기능들을 포함한 `PlayerHealth` 시스템을 구현했다.

* 현재 HP와 최대 HP 관리
* 피해 및 회복 처리
* 사망 상태 처리
* HP 변경 이벤트 발생
* 가드 성공 시 피해 대신 Heat 증가
* 사망 시 플레이어 입력 비활성화

<br>

`PlayerHealth`는 HP가 변경될 때 `OnHPChanged` 이벤트를 발생시키도록 구성되어 있었다.

```csharp
public event Action<int, int> OnHPChanged;

private void NotifyHPChanged()
{
    OnHPChanged?.Invoke(currentHP, maxHP);
}
```

이 부분은 HP 시스템을 담당한 팀원이 구현한 코드이다.

<br>

나는 해당 시스템이 프로젝트에 병합된 뒤, 미리 제작해 두었던 `HPDrawer`와 HUD 오브젝트가 실제 `PlayerHealth`의 데이터를 받을 수 있도록 씬과 Inspector 참조를 연결했다.

`UIManager`에서는 `PlayerHealth.OnHPChanged` 이벤트를 받아, HP가 변경될 때마다 `HPDrawer.SetHP()`가 호출되도록 구성되어 있었다.

```csharp
private void HandleHPChanged(int currentHP, int maxHP)
{
    _hpDrawer.SetHP(currentHP, maxHP);
}
```

이를 통해 실제 전투의 흐름은 다음과 같이 이어졌다.

<br>

**적의 공격이 플레이어에게 적중**<br>
→ **`PlayerHealth.TakeDamage()` 호출**<br>
→ **현재 HP 감소**<br>
→ **`OnHPChanged` 이벤트 발생**<br>
→ **`UIManager.HandleHPChanged()` 호출**<br>
→ **`HPDrawer.SetHP()` 호출**<br>
→ **HP 게이지와 텍스트 갱신**<br>
→ **이전 HP보다 감소했다면 파티클 재생**

<br>

처음에는 HP 시스템과 UI가 서로 독립적으로 개발되었지만, `OnHPChanged` 이벤트를 기준으로 두 작업을 연결함으로써 실제 전투에서 발생한 피해 결과가 HUD까지 자연스럽게 전달되도록 만들 수 있었다.

## HP가 부족할 때 경고 표시 추가

HP UI가 실제 `PlayerHealth`와 연결된 이후에는, 플레이어의 HP가 일정 비율 이하로 내려갔을 때 시각적인 경고를 표시하는 기능을 추가했다.

Low HP의 기준값은 `UIManager`에서 직접 설정할 수 있도록 구성했다.

```csharp
[Header("UI Conditions")]
[SerializeField] private float lowHPThreshold = 0.2f;
```

기본값은 `0.2`이므로, 현재 HP가 최대 HP의 20% 이하일 때 Low HP 상태로 판단한다.

<br>

HP가 변경될 때에는 현재 HP의 비율을 계산하고, 해당 값이 설정된 기준 이하인지 확인한다.

```csharp
private void HandleHPChanged(int currentHP, int maxHP)
{
    _hpDrawer.SetHP(currentHP, maxHP);

    bool isLowHP =
        (float)currentHP / maxHP <= lowHPThreshold;

    _hpDrawer.SetLowHP(isLowHP);
}
```

또한 플레이 도중에 HP가 변경될 때뿐 아니라, 씬에 처음 진입했을 때 이미 Low HP 상태일 가능성도 고려했다.

따라서 `Start()`에서도 현재 HP를 기준으로 같은 검사를 수행하도록 구성했다.

```csharp
private void Start()
{
    if (_playerHealth != null)
    {
        _hpDrawer.SetHP(
            _playerHealth.CurrentHP,
            _playerHealth.MaxHP
        );

        bool isLowHP =
            (float)_playerHealth.CurrentHP /
            _playerHealth.MaxHP <= lowHPThreshold;

        _hpDrawer.SetLowHP(isLowHP);
    }
}
```

이를 통해 다음 두 상황 모두에서 Low HP 상태가 정상적으로 반영된다.

* 게임을 시작하거나 씬에 진입했을 때
* 플레이 도중 HP가 변경되었을 때

## 코루틴을 이용한 Low HP 점멸 효과

Low HP 상태가 되면 HP Fill이 일반 색상과 경고 색상 사이를 오가며 점멸하도록 만들었다.

```csharp
public void SetLowHP(bool active)
{
    if (isLowHP == active)
        return;

    isLowHP = active;

    if (active)
    {
        blinkRoutine = StartCoroutine(LowHPBlink());
    }
    else
    {
        if (blinkRoutine != null)
        {
            StopCoroutine(blinkRoutine);
            blinkRoutine = null;
        }

        hpFill.color = normalColor;
    }
}
```

가장 먼저 현재 Low HP 상태와 새롭게 전달받은 상태가 동일하다면 아무 작업도 하지 않도록 했다.

이를 통해 HP가 변경될 때마다 같은 코루틴이 여러 번 중복으로 실행되는 것을 방지했다.

<br>

Low HP 상태가 시작되면 점멸 코루틴을 실행한다.

반대로 HP가 회복되어 Low HP 상태에서 벗어나면 실행 중인 코루틴을 중지하고, HP Fill의 색상을 다시 일반 상태로 되돌린다.

<br>

실제 점멸 패턴은 다음과 같이 구성했다.

```csharp
IEnumerator LowHPBlink()
{
    while (true)
    {
        yield return Blink(0.16f);
        yield return new WaitForSeconds(0.6f);

        yield return Blink(0.16f);
        yield return new WaitForSeconds(0.16f);
    }
}
```

짧게 한 번 깜빡인 뒤 잠시 기다리고, 다시 한 번 빠르게 깜빡이는 패턴을 반복한다.

단순하게 일정 간격으로 색상을 바꾸는 것보다, 조금 더 위험 경고에 가까운 느낌을 줄 수 있도록 점멸 간격을 다르게 구성했다.

<br>

색상이 변화하는 과정에는 `Color.Lerp()`를 사용했다.

```csharp
IEnumerator Blink(float duration)
{
    float t = 0;

    while (t < duration)
    {
        t += Time.deltaTime;

        float alpha =
            Mathf.Sin(t / duration * Mathf.PI);

        hpFill.color =
            Color.Lerp(normalColor, warningColor, alpha);

        yield return null;
    }

    hpFill.color = normalColor;
}
```

`Mathf.Sin()`을 사용하여 점멸의 시작과 끝에서는 일반 색상에 가깝고, 중간 지점에서 경고 색상이 가장 강하게 나타나도록 했다.

<br>

기본 경고 색상은 붉은 계열로 지정했다.

```csharp
[SerializeField]
private Color normalColor = Color.white;

[SerializeField]
private Color warningColor =
    new Color(1f, 0.4f, 0.4f);
```

이 기능을 통해 플레이어는 HP 수치를 직접 읽지 않더라도, HP 바의 색상 변화를 통해 현재 위험 상태에 진입했다는 사실을 바로 인지할 수 있다.

<br>

**[이미지 5 삽입 — Low HP 상태에서 붉게 점멸하는 HP 바]**

<br>

> 현재 HP가 최대 HP의 20% 이하로 내려가면 HP Fill이 붉은 경고 색상으로 점멸한다.

## 既存のHeat・Core HUDと統一されたHP UIの構成

HP UIは、既存のHeat・Core UIと同じHUD内に配置した。

<br>

HP領域は以下のように構成した。

* `HPFrame`: HPバーの背景および外枠
* `HPFill`: 現在HPの割合に応じて減少する画像
* `HPText`: 現在HPと最大HPを表示するテキスト
* `HPParticle`: HPが減少した際に再生されるパーティクル

<br>

HPデータは`HPDrawer.SetHP()`を通して画面へ反映するようにした。

```csharp
public void SetHP(int current, int max)
{
    if (max <= 0)
        return;

    float fill = (float)current / max;

    hpFill.fillAmount = fill;

    if (hpText != null)
        hpText.text = $"{current}/{max}";

    previousHP = current;
}
```

現在HPを最大HPで割り、`0~1`の範囲の割合へ変換した後、その値を`hpFill.fillAmount`へ渡した。

<br>

例えば現在HPが75、最大HPが100であれば、以下のように表示される。

* HPバーのFill割合: `0.75`
* HPテキスト: `75/100`

<br>

このように現在値と最大値を一緒に表示することで、プレイヤーは残りHPの割合だけでなく、正確な数値も同時に確認できるようにした。

## HPが減少したときだけパーティクルを再生する

単純にHP UIが更新されるたびにパーティクルを再生すると、問題が発生する。

シーン開始時に初期HPを表示するときや、プレイヤーがHPを回復した状況でも、ダメージを受けたかのようにパーティクルが再生されてしまう可能性があるためである。

<br>

これを防ぐため、以前のHP値を保存しておき、新しいHPが以前の値より小さくなった場合だけパーティクルを再生するようにした。

```csharp
private int previousHP = -1;

public void SetHP(int current, int max)
{
    if (max <= 0)
        return;

    float fill = (float)current / max;

    if (previousHP != -1 &&
        current < previousHP &&
        hpParticle != null)
    {
        MoveParticle(fill);
        hpParticle.Play();
    }

    hpFill.fillAmount = fill;

    if (hpText != null)
        hpText.text = $"{current}/{max}";

    previousHP = current;
}
```

`previousHP`の初期値は`-1`に設定した。

最初にUIを初期化する際には、比較する以前のHPが存在しないため、この時点ではパーティクルを再生しない。

<br>

2回目の更新からは、以下の三つの条件を確認する。

* 以前のHP値が存在するか
* 現在HPが以前のHPより減少しているか
* 使用するパーティクルシステムが接続されているか

<br>

三つの条件をすべて満たした場合にのみ、HP減少パーティクルを再生する。

これにより、状況に応じて以下のように動作させることができた。

* シーン開始時に最大HPを表示 → パーティクルを再生しない
* HP回復 → パーティクルを再生しない
* 同じHP値で再度更新 → パーティクルを再生しない
* ダメージを受けてHP減少 → パーティクルを再生

<br>

単純に`SetHP()`が呼び出されたかどうかを基準に判断するのではなく、**実際にHPが減少したかを比較し、ダメージエフェクトが必要な瞬間を区別** したのである。

## 減少したHPバーの端へパーティクルを移動する

HP減少パーティクルは、HPバーの固定された位置で再生するのではなく、HPが減少した後に残っているFillの端部分で再生されるようにした。

プレイヤーがダメージを受けるとHPバーが減少し、その減少した境界部分でパーティクルが発生する方式である。

```csharp
private void MoveParticle(float fill)
{
    RectTransform rt = hpFill.rectTransform;

    float x = rt.rect.xMin + rt.rect.width * fill;

    Vector3 worldPos =
        rt.TransformPoint(new Vector3(x, 0, 0));

    hpParticle.transform.position = worldPos;
}
```

まず`HPFill`画像の`RectTransform`を取得する。

その後、現在のHP割合を利用して、画像内部でFillが終わるX座標を計算する。

<br>

計算方法は以下の通りである。

**HP Fillの左側座標 +（HP Fill全体の幅 × 現在HPの割合）= 現在のHPバーが終わる位置**

<br>

この位置はUIオブジェクトのローカル座標であるため、`TransformPoint()`を利用してワールド座標へ変換した後、パーティクルの位置に適用した。

例えばHPが100%であれば、パーティクルはHPバーの右端付近に位置し、HPが30%であれば左側から30%の地点へ移動する。

<br>

**[画像2を挿入 — HP減少時にFillの端で再生されるパーティクル]**

<br>

> HPが減少すると、残っているHP Fillの端へパーティクルを移動させてから再生する。HPバーが減少する位置とダメージエフェクトが一致するよう構成した。

<br>

単純に数字とゲージだけを変化させるよりも、**HPが実際に削られていく位置に視覚効果を配置することで、ダメージをより直接的に感じられるように** したかった。

## パーティクルをUI上に表示するためCanvas設定を変更する

HP減少パーティクルは、Unityの`ParticleSystem`を使用して制作した。

しかし、既存のCanvasは`Screen Space - Overlay`方式でレンダリングされていた。

Overlay方式のCanvasは、一般的なワールド空間のパーティクルより前に描画されるため、パーティクルがUIの後ろに隠れたり、意図した順序で表示されなかったりする問題が発生する可能性があった。

<br>

これを解決するため、CanvasのRender Modeを以下のように変更した。

* 変更前: `Screen Space - Overlay`
* 変更後: `Screen Space - Camera`
* Render Camera: `Main Camera`
* Plane Distance: `1`

<br>

CanvasがMain Cameraを基準としてレンダリングされるよう変更した後、パーティクルのSorting Orderを調整し、HP UI上に正常に表示できるようにした。

この変更はコードではなく、UnityのシーンとCanvas設定へ直接保存される値であった。

そのため、ほかのチームメンバーが同じCanvasを修正した後にマージした場合、Render ModeやRender Cameraの参照で競合が発生する可能性があった。

<br>

そのため、作業直後にチームのDiscordへ以下のように変更内容を共有した。

> HP Particleを実装する過程で、CanvasのRender ModeをCanvas(Screen Space - Overlay)からCanvas(Screen Space - Camera)へ変更しました。Main CameraをRender Cameraとして指定して使用しています。そのため、Mergeする過程でCanvas側のRender Mode関連で競合が発生する可能性がありますので、参考にしてください。

<br>

単純に変更内容をコミットして終わるのではなく、ほかのチームメンバーがマージする際に確認する必要があるUnityシーン設定まで一緒に共有した。

Unityのシーンやプレハブは、コードのように変更内容を一目で把握するのが難しい場合が多い。

特にCanvasのCamera参照のように、シーンオブジェクトと直接接続される設定は、マージの過程で参照が失われたり別の値へ変更されたりする可能性があるため、別途確認する必要があった。

<br>

HP減少VFXを最初に実装した7月20日午前1時頃には、プレイヤーHPシステムはまだプロジェクトに存在していなかった。

しかし同日その後、チームメンバーが以下の機能を含む`PlayerHealth`システムを実装した。

* 現在HPと最大HPの管理
* ダメージおよび回復処理
* 死亡状態の処理
* HP変更イベントの発生
* ガード成功時、ダメージの代わりにHeat増加
* 死亡時にプレイヤー入力を無効化

<br>

`PlayerHealth`は、HPが変更された際に`OnHPChanged`イベントを発生させるよう構成されていた。

```csharp
public event Action<int, int> OnHPChanged;

private void NotifyHPChanged()
{
    OnHPChanged?.Invoke(currentHP, maxHP);
}
```

この部分はHPシステムを担当したチームメンバーが実装したコードである。

<br>

私はこのシステムがプロジェクトへマージされた後、あらかじめ制作しておいた`HPDrawer`とHUDオブジェクトが実際の`PlayerHealth`データを受け取れるよう、シーンとInspectorの参照を接続した。

`UIManager`では`PlayerHealth.OnHPChanged`イベントを受け取り、HPが変更されるたびに`HPDrawer.SetHP()`が呼び出されるよう構成されていた。

```csharp
private void HandleHPChanged(int currentHP, int maxHP)
{
    _hpDrawer.SetHP(currentHP, maxHP);
}
```

これにより、実際の戦闘の流れは以下のように繋がった。

<br>

**敵の攻撃がプレイヤーに命中**<br>
→ **`PlayerHealth.TakeDamage()`を呼び出す**<br>
→ **現在HPが減少**<br>
→ **`OnHPChanged`イベントが発生**<br>
→ **`UIManager.HandleHPChanged()`を呼び出す**<br>
→ **`HPDrawer.SetHP()`を呼び出す**<br>
→ **HPゲージとテキストを更新**<br>
→ **以前のHPより減少していればパーティクルを再生**

<br>

最初はHPシステムとUIがそれぞれ独立して開発されていたが、`OnHPChanged`イベントを基準として二つの作業を接続することで、実際の戦闘で発生したダメージの結果がHUDまで自然に伝わるようにすることができた。

## HPが少ないときに警告表示を追加する

HP UIを実際の`PlayerHealth`へ接続した後は、プレイヤーのHPが一定の割合以下まで減少した際に、視覚的な警告を表示する機能を追加した。

Low HPの基準値は、`UIManager`から直接設定できるよう構成した。

```csharp
[Header("UI Conditions")]
[SerializeField] private float lowHPThreshold = 0.2f;
```

初期値は`0.2`であるため、現在HPが最大HPの20%以下になった場合、Low HP状態だと判断する。

<br>

HPが変更された際には、現在HPの割合を計算し、その値が設定された基準以下であるかを確認する。

```csharp
private void HandleHPChanged(int currentHP, int maxHP)
{
    _hpDrawer.SetHP(currentHP, maxHP);

    bool isLowHP =
        (float)currentHP / maxHP <= lowHPThreshold;

    _hpDrawer.SetLowHP(isLowHP);
}
```

また、プレイ中にHPが変更された場合だけでなく、シーンへ最初に入った時点ですでにLow HP状態である可能性も考慮した。

そのため、`Start()`でも現在HPを基準として同じ判定を行うよう構成した。

```csharp
private void Start()
{
    if (_playerHealth != null)
    {
        _hpDrawer.SetHP(
            _playerHealth.CurrentHP,
            _playerHealth.MaxHP
        );

        bool isLowHP =
            (float)_playerHealth.CurrentHP /
            _playerHealth.MaxHP <= lowHPThreshold;

        _hpDrawer.SetLowHP(isLowHP);
    }
}
```

これにより、以下の二つの状況のどちらでもLow HP状態が正常に反映される。

* ゲーム開始時、またはシーンへ入ったとき
* プレイ中にHPが変更されたとき

## コルーチンを利用したLow HP点滅エフェクト

Low HP状態になると、HP Fillが通常色と警告色の間を行き来しながら点滅するようにした。

```csharp
public void SetLowHP(bool active)
{
    if (isLowHP == active)
        return;

    isLowHP = active;

    if (active)
    {
        blinkRoutine = StartCoroutine(LowHPBlink());
    }
    else
    {
        if (blinkRoutine != null)
        {
            StopCoroutine(blinkRoutine);
            blinkRoutine = null;
        }

        hpFill.color = normalColor;
    }
}
```

まず、現在のLow HP状態と新たに渡された状態が同じであれば、何も処理しないようにした。

これにより、HPが変更されるたびに同じコルーチンが何度も重複して実行されることを防いだ。

<br>

Low HP状態が始まると、点滅用のコルーチンを実行する。

反対に、HPが回復してLow HP状態から抜けた場合は、実行中のコルーチンを停止し、HP Fillの色を通常状態へ戻す。

<br>

実際の点滅パターンは、以下のように構成した。

```csharp
IEnumerator LowHPBlink()
{
    while (true)
    {
        yield return Blink(0.16f);
        yield return new WaitForSeconds(0.6f);

        yield return Blink(0.16f);
        yield return new WaitForSeconds(0.16f);
    }
}
```

短く一度点滅した後にしばらく待ち、もう一度素早く点滅するパターンを繰り返す。

単純に一定間隔で色を変えるよりも、少しでも危険警告らしい印象を与えられるよう、点滅の間隔を変えて構成した。

<br>

色が変化する過程には`Color.Lerp()`を使用した。

```csharp
IEnumerator Blink(float duration)
{
    float t = 0;

    while (t < duration)
    {
        t += Time.deltaTime;

        float alpha =
            Mathf.Sin(t / duration * Mathf.PI);

        hpFill.color =
            Color.Lerp(normalColor, warningColor, alpha);

        yield return null;
    }

    hpFill.color = normalColor;
}
```

`Mathf.Sin()`を使用することで、点滅の開始と終了では通常色に近く、中間地点では警告色が最も強く現れるようにした。

<br>

基本となる警告色は、赤系統に設定した。

```csharp
[SerializeField]
private Color normalColor = Color.white;

[SerializeField]
private Color warningColor =
    new Color(1f, 0.4f, 0.4f);
```

この機能によって、プレイヤーはHPの数値を直接読まなくても、HPバーの色の変化を通して、現在危険な状態に入っていることをすぐに認識できる。
