3주차에는 기존 HUD를 사이버펑크 스타일로 리메이크하고, Heat 상태 효과와 Skill 아이콘, 사망 연출을 추가했다.

## ESC 입력을 Input System에 추가하기

가장 먼저 Unity Input System의 `InputSystem_Actions`에 Pause 입력을 추가했다.

게임 플레이 중 ESC 키를 눌렀을 때 사용할 `Pause` Action을 `Player` Action Map에 추가하고, Pause 화면으로 진입한 이후에도 같은 ESC 키로 게임을 재개할 수 있도록 `UI` Action Map의 `Cancel`에도 ESC를 연결했다.

<br>

입력 구조는 다음과 같이 구성했다.

* `Player` Action Map의 `Pause` → ESC
* `UI` Action Map의 `Cancel` → ESC
* 두 입력 모두 `PauseManager.OnPause()` 호출
* Pause 진입 시 Action Map을 `Player`에서 `UI`로 변경
* Resume 시 다시 `UI`에서 `Player`로 복귀

<br>

Pause 입력을 받는 메서드에서는 입력이 실제 수행된 시점인지 먼저 확인했다.

```csharp
public void OnPause(InputAction.CallbackContext context)
{
    if (!context.performed)
        return;

    TogglePause();
}
```

`InputAction.CallbackContext`는 Action의 시작, 수행, 취소 등 여러 단계에서 호출될 수 있기 때문에, `context.performed`를 확인해 ESC 입력이 실제로 처리된 순간에만 `TogglePause()`가 실행되도록 했다.

<br>

현재 Pause 상태에 따라 게임을 일시정지하거나 재개한다.

```csharp
public void TogglePause()
{
    if (isPaused)
        Resume();
    else
        Pause();
}
```

게임 플레이 중 ESC를 누르면 Pause 상태로 진입하고, Pause 화면에서 ESC를 다시 누르면 Resume 상태로 돌아가도록 구성했다.

## 게임 일시정지 처리

Pause 상태에 진입할 때에는 단순히 Pause Panel만 화면에 띄우지 않았다.

게임 시간, 플레이어 입력, 마우스 커서, Input Action Map을 함께 변경하여 **플레이 상태 자체를 UI 조작 상태로 전환** 하도록 만들었다.

```csharp
private void Pause()
{
    if (isPaused)
        return;

    isPaused = true;
    Time.timeScale = 0f;

    playerController.SetInputEnabled(false);
    pausePanel.SetActive(true);

    Cursor.visible = true;

    playerInput.SwitchCurrentActionMap("UI");
}
```

Pause 상태에서는 다음과 같은 처리가 이루어진다.

1. 중복 Pause 실행을 방지한다.
2. `isPaused`를 `true`로 변경한다.
3. `Time.timeScale`을 `0`으로 설정한다.
4. 플레이어 조작 입력을 비활성화한다.
5. Pause Panel을 활성화한다.
6. 마우스 커서를 표시한다.
7. Input Action Map을 `Player`에서 `UI`로 전환한다.

<br>

`Time.timeScale = 0`으로 설정하면 `Time.deltaTime`을 기준으로 동작하는 이동이나 애니메이션, 그리고 Scaled Time을 사용하는 처리들이 정지한다.

여기에 플레이어 컨트롤러의 입력까지 비활성화함으로써, Pause 상태에서 이동이나 공격이 발생하지 않도록 했다.

또한 이후 Resume, Setting, Exit와 같은 버튼을 마우스로 조작할 수 있도록 커서를 화면에 표시했다.

<br>

**[캡처 2 삽입 — 일반 플레이 화면과 ESC Pause 화면 비교]**

<br>

> ESC 키를 누르면 게임의 시간과 플레이어 입력이 정지하고, 마우스 커서와 Pause 화면이 활성화된다.

## 게임 재개 처리

Resume 상태에서는 Pause 과정에서 변경했던 값들을 다시 원래 상태로 복구한다.

```csharp
private void Resume()
{
    if (!isPaused)
        return;

    isPaused = false;
    Time.timeScale = 1f;

    playerController.SetInputEnabled(true);
    pausePanel.SetActive(false);

    Cursor.visible = false;

    playerInput.SwitchCurrentActionMap("Player");
}
```

Resume 시에는 다음과 같은 순서로 상태를 되돌린다.

1. `isPaused`를 `false`로 변경한다.
2. `Time.timeScale`을 `1`로 복구한다.
3. 플레이어 입력을 다시 활성화한다.
4. Pause Panel을 숨긴다.
5. 마우스 커서를 숨긴다.
6. Input Action Map을 `UI`에서 `Player`로 되돌린다.

<br>

Pause Panel의 Resume 버튼에서도 사용할 수 있도록 공개 메서드 역시 준비했다.

```csharp
public void ResumeGame()
{
    Resume();
}
```

다만 이번 주 커밋에는 `Button_Resume` 오브젝트와 `ResumeGame()` 메서드까지는 존재하지만, 버튼의 `OnClick`에 해당 메서드를 실제로 연결한 기록은 남아 있지 않았다.

따라서 이번 주에 확실하게 동작하는 재개 방식은 **ESC 키를 다시 누르는 방식** 이고, Resume 버튼은 추후 실제 기능을 연결할 수 있도록 준비한 단계였다.

<br>

추가로 오브젝트가 파괴될 때 `Time.timeScale`이 `0`으로 남는 상황을 막기 위한 방어 코드도 추가했다.

```csharp
private void OnDestroy()
{
    Time.timeScale = 1f;
}
```

씬을 종료하거나 `PauseManager`가 파괴되는 과정에서 `Time.timeScale`이 `0`인 상태로 남으면, 다음 씬에서도 게임이 멈춘 것처럼 보일 수 있다.

이를 방지하기 위해 오브젝트가 파괴될 때 기본값인 `1`로 복구하도록 했다.

## Pause 화면 레이아웃 계획

Pause 화면은 최종적으로 좌우 영역을 나누어 사용하는 형태로 계획했다.

좌측에는 플레이어가 직접 선택할 수 있는 메뉴를 배치하고, 우측에는 게임의 상태와 인벤토리를 보여주는 구조다.

### 좌측 메뉴 계획

* Resume
* Setting
* Exit
* 필요에 따라 추가되는 메뉴 버튼

### 우측 정보 계획

* 플레이어 현재 상태
* 현재 HP와 Heat
* 장착 중인 Core
* 보유 Core 또는 아이템
* 인벤토리
* 기타 상태 정보

<br>

이번 주에는 Pause Panel과 배경, 그리고 각종 버튼을 배치할 수 있는 기본 영역부터 만들었다.

테스트 씬에는 `Button_Resume`과 여러 테스트용 버튼 오브젝트가 추가되었지만, 실제 Setting·Exit·Inventory 기능은 아직 연결하지 않았다.

## Pause 중에도 Core가 전환되는 문제

Pause 상태에서는 플레이어 컨트롤러의 입력을 비활성화하고, Action Map도`UI`로 전환했다.

하지만 테스트 과정에서 **Pause 상태에서도 숫자 키를 이용해 Core를 전환할 수 있는 문제** 가 남아 있다는 것을 확인했다.

<br>

당시 작업 기록에도 다음과 같이 남겼다.

> 현재 Pause 상태에서도 Core 전환이 가능한 문제가 있습니다. 다만 이 부분은 제가 해결할 수 있는 부분은 아닌 듯해 일단 건드리지 않았습니다. 현재 Pause는 TimeScale을 0으로 하는 방식으로 구현해둔 상태입니다.

<br>

원인은 Core 전환 입력이 `PlayerController2D`나 Input System의 Action Map을 통해 처리되지 않고, `CoreManager.Update()`에서 기존 Input API로 직접 키 입력을 확인하고 있었기 때문이다.

```csharp
private void Update()
{
    for (int i = 0; i < coreSlots.Count; i++)
    {
        CoreSlot slot = coreSlots[i];

        if (slot == null || slot.SelectKey == KeyCode.None)
            continue;

        if (Input.GetKeyDown(slot.SelectKey))
            SetCurrentCore(i);
    }
}
```

`Time.timeScale`을 `0`으로 설정하더라도 Unity의`Update()` 호출이나 키 입력 확인 자체가 완전히 중단되는 것은 아니다.

또한 `CoreManager`는 현재 `PlayerInput`의 Action Map이 `Player`인지 `UI`인지 확인하지 않고 직접 숫자 키 입력을 읽고 있었다.

<br>

따라서 PauseManager에서 다음과 같은 처리를 모두 수행하더라도 Core 전환은 별도로 차단되지 않았다.

* 플레이어 컨트롤러 입력 비활성화
* `Player` Action Map에서 `UI` Action Map으로 전환
* `Time.timeScale = 0`

<br>

이를 해결하려면 `CoreManager`가 Pause 상태나 공용 입력 잠금 상태를 확인하도록 만들거나, Core 전환 입력 자체를 Input System Action으로 통합할 필요가 있었다.

하지만 이는 단순한 Pause UI 수정이 아니라 **Core 시스템의 입력 처리 방식까지 변경해야 하는 문제** 였다.

따라서 이번 주에는 다른 팀원이 담당한 Core 시스템을 임의로 변경하지 않고, 원인과 해결 방향만 확인한 상태로 남겨두었다.

단순히 “Pause에서 Core가 바뀌는 버그가 있다”로 끝나는 문제가 아니라, **서로 다른 입력 방식이 하나의 프로젝트 안에서 섞여 있을 때 Pause 같은 전역 상태 제어가 어려워질 수 있다는 점을 확인한 사례** 였다.

<br>

**[선택 캡처 4 삽입 — Pause 중 Core가 전환되는 알려진 문제]**

<br>

> Pause 상태에서도 `CoreManager`가 숫자 키를 직접 확인하고 있어 Core 전환이 가능했다. Pause UI만으로 해결할 수 있는 문제가 아니라 Core 입력 구조와 함께 수정해야 하는 항목으로 분리했다.

## UI 에셋 및 폴더 구조 정리

4주차에는 UI 관련 에셋의 위치도 정리했다.

기존에는 `Assets/jhkim` 아래에 UI 관련 파일들이 위치해 있었지만, 이를 `Assets/WorkSpace/jhkim`으로 이동하여 팀 프로젝트의 작업 폴더 구조에 맞췄다.

<br>

이동된 항목에는 다음과 같은 파일들이 포함되어 있었다.

* HUD 프리팹
* HP·Heat·Core Drawer
* Skill UI 관련 코드
* Death UI 관련 코드
* UI 테스트 씬
* 폰트
* Material 및 Shader Graph
* 임시 UI 이미지

<br>

파일을 이동할 때에는 `.meta` 파일 역시 함께 유지하여 Unity 에셋의 GUID 참조가 끊어지지 않도록 했다.

또한 사용하지 않게 된 임시 에셋들은 바로 삭제하지 않고 `TrashCan` 폴더로 옮겼다.

팀 프로젝트에서는 내가 사용하지 않는다고 생각한 에셋이 다른 씬이나 프리팹에서 참조되고 있을 가능성이 있기 때문에, 바로 제거하기보다 먼저 분리해서 보관하는 쪽을 선택했다.

## Core 1 디자인 개선

Pause 화면 작업과 함께 Core 1의 UI 디자인도 일부 개선했다.

기존 Core 1 아이콘을 새로운 사이버펑크 스타일의 이미지로 교체하고, 해당 이미지를 `Core_01`의 ScriptableObject 데이터에 다시 연결했다.

이 변경은 코드가 아니라 `Core_01.asset`의 `coreIcon` 참조를 새로운 이미지로 변경하는 방식으로 이루어졌다.

<br>

3주차에는 Core 이름과 아이콘을 화면에 표시하는 기능을 만들었다면, 4주차에는 실제로 화면에 표시되는 **Core 1 아이콘 자체의 디자인을 개선한 것** 이다.

이번 주에는 우선 Core 1을 먼저 수정하고, 이후 동일한 디자인 규칙을 Core 2와 Core 3에도 적용할 계획을 세웠다.

Heat 게이지 역시 추후 Core UI와 디자인적인 통일감을 가질 수 있도록 다시 조정할 예정이었다.

다만 Core 2·3의 신규 디자인과 Heat 게이지의 추가 리메이크는 이번 주의 완료 범위에는 포함하지 않았다.

<br>

## 범용 UI Shader Graph 실험

Pause 화면의 배경에는 단순한 정적 이미지 대신, 『ERROR-CODE-H』의 사이버펑크 분위기에 어울리는 동적 셰이더를 적용하고자 했다.

처음에는 Pause 화면에만 사용하는 셰이더를 만드는 대신, 여러 UI에서 공통으로 재사용할 수 있는 **범용 UI Shader Graph** 를 제작하는 방향으로 시도했다.

<br>

구성한 기능은 다음과 같다.

* Appearance
* Distortion
* Glow
* Gradient
* Mask
* Noise
* Pixelize
* Reveal
* Scan

<br>

각각의 기능은 Sub Graph로 나누고, 이를 하나의 `SG_UIFramework`에서 조합하는 구조를 만들었다.

목표는 Material에서 필요한 효과만 선택해 사용할 수 있도록 만드는 것이었다.

<br>

예를 들어 UI 종류에 따라 다음과 같은 방식으로 활용하는 것을 생각했다.

* Core 아이콘 → Glow, Reveal
* 일반 패널 → Gradient, Mask
* 강조 UI → Pixelize, Scan

<br>

<br>

처음 시도한 구조가 원하는 대로 동작하지 않았지만, 문제를 숨기거나 완성된 기능처럼 처리하지 않고 **현재 한계와 다음 구현 방향을 그대로 기록** 했다.

## Shader Graph에서 HLSL 기반 셰이더로 전환

Shader Graph 기반의 범용 셰이더에서 UI Mask 문제가 발생하자, Pause 배경용 셰이더는 HLSL 기반의 `Shader_Background.shader`로 다시 제작했다.

<br>

셰이더에는 다음과 같은 속성을 마련했다.

```hlsl
_TintColor("TintColor", Color) = (1, 1, 1, 1)
_Opacity("Opacity", Range(0, 1)) = 1
_Progress("Progress", Range(0, 1)) = 1
_PixelCount("PixelCount", Range(1, 1024)) = 128
_GlowIntensity("GlowIntensity", Range(0, 5)) = 1
_ScanSpeed("ScanSpeed", Range(-5, 5)) = 1
_NoiseStrength("NoiseStrength", Range(0, 1)) = 0.2
_DistortionStrength("DistortionStrength", Range(0, 0.1)) = 0
```

이러한 값을 통해 하나의 Material 안에서 다음과 같은 표현을 조정할 수 있도록 했다.

* UI 색조
* 투명도
* 좌우 진행도
* 픽셀화 정도
* Glow 강도
* Scan 속도
* Noise 강도
* Distortion 강도

<br>

Shader Graph에서 문제가 되었던 UI Mask와의 호환을 위해 Stencil 관련 속성도 직접 추가했다.

```hlsl
_Stencil("Stencil Ref", Float) = 0
_StencilComp("Stencil Comp", Float) = 8
_StencilOp("Stencil Op", Float) = 0
_StencilReadMask("Stencil Read Mask", Float) = 255
_StencilWriteMask("Stencil Write Mask", Float) = 255
_ColorMask("Color Mask", Float) = 15
```

처음 만든 Shader Graph 구조를 그대로 고집하기보다, 실제 UI에서 필요했던 Mask와 Stencil 처리를 직접 다룰 수 있도록 HLSL 기반으로 방향을 바꾼 것이다.

이번 작업을 통해 **구현하기 편한 방식과 실제 요구사항을 만족하는 방식이 항상 같지는 않다는 점** 을 다시 느낄 수 있었다.

## Pause 중에도 셰이더가 움직이도록 만들기

Pause 상태에서는 `Time.timeScale`이 `0`이 된다.

그런데 Pause 화면의 Noise, Scan, Distortion 효과까지 함께 멈춰버리면, 화면 전체가 단순한 정지 이미지처럼 보이게 된다.

이번 Pause 화면은 게임 자체는 멈추더라도 인터페이스는 계속 살아 움직이는, 일종의 시스템 화면처럼 보이기를 원했다.

<br>

그래서 셰이더의 시간 값을 게임 시간과 분리할 필요가 있었다.

이를 위해 `Time.unscaledTime`을 전역 셰이더 값으로 전달하는 `DontStopShader`를 추가했다.

```csharp
private void UpdateTimeParams()
{
    float t = Time.unscaledTime;

    Shader.SetGlobalVector("_UnscaledTimeParams", new Vector4(t * xScale, t * yScale, t * zScale, t * wScale));
}
```

`Time.unscaledTime`은 `Time.timeScale`의 영향을 받지 않는다.

따라서 게임 시간이 멈춰 있어도 `_UnscaledTimeParams`는 계속 증가하고, Pause 배경 셰이더의 애니메이션을 유지할 수 있다.

<br>

셰이더에서는 Unity의 기본 Time Parameter 대신 전달받은 Unscaled Time을 사용하도록 했다.

```hlsl
float4 _UnscaledTimeParams;
```

이를 통해 **게임 플레이는 완전히 정지해 있지만 Pause 화면의 Scan과 Noise는 계속 움직이는 상태** 를 만들 수 있었다.

<br>

**[캡처 7 삽입 — Pause 중에도 움직이는 Scan 또는 Noise 효과]**

<br>

> `Time.timeScale`이 `0`인 Pause 상태에서도 UI 셰이더가 움직이도록 `Time.unscaledTime`을 전역 셰이더 값으로 전달했다.

이 기능은 정적인 이미지보다 2~3초 정도의 GIF나 짧은 영상으로 보여주는 편이 훨씬 잘 드러날 것 같다.

## 마우스 위치에 반응하는 Pause 배경

Pause 화면에서는 마우스를 움직일 때 배경 표현도 함께 변화하도록 `PauseMouseController`를 추가했다.

먼저 Pause Panel을 기준으로 마우스의 로컬 좌표를 계산했다.

```csharp
RectTransformUtility.ScreenPointToLocalPointInRectangle(panelRect, Input.mousePosition, cam, out Vector2 localPoint);

Rect rect = panelRect.rect;

float mouseX = Mathf.InverseLerp(rect.xMin, rect.xMax, localPoint.x);
mouseX = Mathf.Clamp01(mouseX);
```

마우스의 X좌표를 `0~1` 사이의 값으로 정규화한 뒤, 이를 다시 좌우 방향을 나타내는 값으로 변환했다.

```csharp
float signed = (0.5f - mouseX) * 2f;
float amplified = Mathf.Clamp(signed * amplify, -1f, 1f);
float target = center + amplified * moveRange;
```

마우스가 화면 중앙에 있을 때는 기준값인 `center`를 사용하고, 좌우로 이동할수록 `moveRange` 범위 안에서 목표값이 달라지도록 했다.

<br>

값이 갑자기 튀지 않도록 `Lerp()`를 사용해 부드럽게 이동시켰다.

이 과정에서도 Pause 상태의 영향을 받지 않도록 `Time.unscaledDeltaTime`을 사용했다.

```csharp
float t = Mathf.Clamp01(lerpSpeed * Time.unscaledDeltaTime);
progress = Mathf.Lerp(progress, target, t);
```

계산된 값은 Material과 전역 Shader 변수 양쪽에 전달했다.

```csharp
materialInstance.SetFloat("_Progress", progress);
Shader.SetGlobalFloat("_GlobalProgress", progress);
```

전체 흐름을 정리하면 다음과 같다.

**마우스 좌우 이동**<br>
→ **Pause Panel 기준 로컬 좌표 계산**<br>
→ **X좌표를 `0~1`로 정규화**<br>
→ **목표 Progress 계산**<br>
→ **Unscaled Delta Time으로 부드럽게 보간**<br>
→ **Material의 `_Progress` 변경**<br>
→ **Pause 배경 표현 변화**

<br>

이 기능을 통해 Pause 화면은 단순히 움직이는 배경에서 한 단계 더 나아가, **플레이어의 마우스 움직임에 반응하는 인터페이스** 가 되었다.

<br>

**[캡처 8 삽입 — 마우스 좌·중앙·우 위치에 따른 Pause 배경 비교]**

<br>

> Pause 화면에서 마우스를 좌우로 움직이면 셰이더의 `_Progress` 값이 달라지고, 그에 따라 배경 표현이 유동적으로 변화한다.

이 기능 역시 정적인 비교 이미지보다 GIF로 보여주는 편이 실제 느낌을 전달하기에 더 적합할 것 같다.

여기까지만 보면 비교적 평범한 Pause 기능이지만, 배경은 단순한 반투명 이미지로 끝내고 싶지 않았다.

『ERROR-CODE-H』의 분위기에 맞춰 Scan, Noise, Distortion, Glow 등을 조합할 수 있는 범용 UI Shader Graph를 먼저 시도했고, UI Mask가 정상적으로 동작하지 않는 문제가 발생하자 HLSL 기반 구현으로 방향을 바꿨다.

처음 만든 방식이 실패했지만, 그대로 억지로 끌고 가기보다 문제를 기록하고 다른 구현 방식으로 전환했다.

<br>

또한 `Time.timeScale`이 `0`인 상태에서도 Pause 화면만큼은 계속 움직일 수 있도록 Unscaled Time을 사용했다.

여기에 마우스의 위치를 셰이더의 `_Progress` 값과 연결하면서, 단순히 움직이는 배경을 넘어 **마우스 움직임에 반응하는 인터페이스** 까지 만들어 볼 수 있었다.

<br>

테스트 과정에서는 Pause 상태에서도 Core 전환이 가능하다는 문제도 발견했다.

PauseManager에서 플레이어 입력을 비활성화하고 Action Map을 UI로 바꾸더라도, `CoreManager`가 별도로 기존 Input API를 사용해 숫자 키를 직접 읽고 있었기 때문이다.

결국 Pause 같은 전역 상태를 제대로 제어하려면, 단순히 하나의 스크립트만 보는 것이 아니라 **프로젝트 전체에서 입력이 어떤 방식으로 처리되고 있는지까지 함께 봐야 한다는 점** 을 알게 되었다.

<br>

이번 주에 인벤토리나 설정 화면까지 완성하지는 못했다.

대신 앞으로 해당 기능을 추가할 수 있는 Pause 화면과 입력 전환 구조, 그리고 『ERROR-CODE-H』의 분위기를 살릴 수 있는 동적 배경의 기반을 만들었다.

1~3주차가 플레이 중 항상 보이는 HUD를 만들어가는 과정이었다면, 4주차부터는 플레이어가 게임과 상호작용하는 **또 하나의 인터페이스 계층** 을 만들기 시작한 셈이다.

## ESC入力をInput Systemに追加する

まずUnity Input Systemの`InputSystem_Actions`へPause入力を追加した。

ゲームプレイ中にESCキーを押した際に使用する`Pause` Actionを`Player` Action Mapへ追加し、Pause画面へ入った後も同じESCキーでゲームを再開できるよう、`UI` Action Mapの`Cancel`にもESCを接続した。

<br>

入力構造は以下のように構成した。

* `Player` Action Mapの`Pause` → ESC
* `UI` Action Mapの`Cancel` → ESC
* どちらの入力も`PauseManager.OnPause()`を呼び出す
* Pause進入時にAction Mapを`Player`から`UI`へ変更
* Resume時には再び`UI`から`Player`へ戻す

<br>

Pause入力を受け取るメソッドでは、入力が実際に実行されたタイミングであるかを先に確認した。

```csharp
public void OnPause(InputAction.CallbackContext context)
{
    if (!context.performed)
        return;

    TogglePause();
}
```

`InputAction.CallbackContext`はActionの開始、実行、キャンセルなど複数の段階で呼び出されるため、`context.performed`を確認し、ESC入力が実際に処理された瞬間だけ`TogglePause()`が実行されるようにした。

<br>

現在のPause状態に応じて、ゲームを一時停止または再開する。

```csharp
public void TogglePause()
{
    if (isPaused)
        Resume();
    else
        Pause();
}
```

ゲームプレイ中にESCを押すとPause状態へ入り、Pause画面で再びESCを押すとResume状態へ戻るよう構成した。

## ゲームの一時停止処理

Pause状態へ入る際には、単純にPause Panelを画面へ表示するだけにはしなかった。

ゲーム時間、プレイヤー入力、マウスカーソル、Input Action Mapを同時に変更し、**プレイ状態そのものをUI操作状態へ切り替える** ようにした。

```csharp
private void Pause()
{
    if (isPaused)
        return;

    isPaused = true;
    Time.timeScale = 0f;

    playerController.SetInputEnabled(false);
    pausePanel.SetActive(true);

    Cursor.visible = true;

    playerInput.SwitchCurrentActionMap("UI");
}
```

Pause状態では、以下の処理が行われる。

1. Pause処理の重複実行を防ぐ。
2. `isPaused`を`true`へ変更する。
3. `Time.timeScale`を`0`へ設定する。
4. プレイヤー操作入力を無効化する。
5. Pause Panelを有効化する。
6. マウスカーソルを表示する。
7. Input Action Mapを`Player`から`UI`へ切り替える。

<br>

`Time.timeScale = 0`へ設定すると、`Time.deltaTime`を基準として動作する移動やアニメーション、Scaled Timeを使用する処理が停止する。

さらにプレイヤーコントローラーの入力も無効化することで、Pause状態で移動や攻撃が発生しないようにした。

また、その後Resume、Setting、Exitなどのボタンをマウスで操作できるよう、カーソルを画面上へ表示した。

<br>

<br>

> ESCキーを押すとゲーム時間とプレイヤー入力が停止し、マウスカーソルとPause画面が有効化される。

## ゲーム再開処理

Resume状態では、Pause処理の中で変更した値を元の状態へ戻す。

```csharp
private void Resume()
{
    if (!isPaused)
        return;

    isPaused = false;
    Time.timeScale = 1f;

    playerController.SetInputEnabled(true);
    pausePanel.SetActive(false);

    Cursor.visible = false;

    playerInput.SwitchCurrentActionMap("Player");
}
```

Resume時には、以下の順序で状態を元に戻す。

1. `isPaused`を`false`へ変更する。
2. `Time.timeScale`を`1`へ戻す。
3. プレイヤー入力を再び有効化する。
4. Pause Panelを非表示にする。
5. マウスカーソルを非表示にする。
6. Input Action Mapを`UI`から`Player`へ戻す。

<br>

Pause PanelのResumeボタンからも使用できるよう、公開メソッドも用意した。

```csharp
public void ResumeGame()
{
    Resume();
}
```

ただし、今週のコミットには`Button_Resume`オブジェクトと`ResumeGame()`メソッドまでは存在しているものの、ボタンの`OnClick`へこのメソッドを実際に接続した記録は残っていなかった。

そのため、今週の時点で確実に動作する再開方法は **ESCキーを再び押す方法** であり、Resumeボタンについては後から実際の機能を接続できるよう準備した段階であった。

<br>

さらに、オブジェクトが破棄された際に`Time.timeScale`が`0`のまま残る状況を防ぐための防御コードも追加した。

```csharp
private void OnDestroy()
{
    Time.timeScale = 1f;
}
```

シーンを終了したり`PauseManager`が破棄されたりする過程で、`Time.timeScale`が`0`のまま残ってしまうと、次のシーンでもゲームが停止しているように見える可能性がある。

これを防ぐため、オブジェクトが破棄された際には初期値である`1`へ戻すようにした。

## Pause中でもCoreが切り替わる問題

Pause状態ではプレイヤーコントローラーの入力を無効化し、Action Mapも`UI`へ切り替えた。

しかしテスト中、**Pause状態でも数字キーを使ってCoreを切り替えられる問題** が残っていることを確認した。

<br>

当時の作業記録にも、以下のように残している。

> 現在Pause状態でもCoreの切り替えが可能な問題があります。ただし、この部分は私の担当範囲だけでは解決できないと思われるため、ひとまず変更していません。現在のPauseはTimeScaleを0にする方式で実装しています。

<br>

原因は、Core切り替え入力が`PlayerController2D`やInput SystemのAction Mapを通して処理されておらず、`CoreManager.Update()`内で従来のInput APIを使い、直接キー入力を確認していたためである。

```csharp
private void Update()
{
    for (int i = 0; i < coreSlots.Count; i++)
    {
        CoreSlot slot = coreSlots[i];

        if (slot == null || slot.SelectKey == KeyCode.None)
            continue;

        if (Input.GetKeyDown(slot.SelectKey))
            SetCurrentCore(i);
    }
}
```

`Time.timeScale`を`0`へ設定しても、Unityの`Update()`呼び出しやキー入力の確認自体が完全に停止するわけではない。

また、`CoreManager`は現在の`PlayerInput` Action Mapが`Player`なのか`UI`なのかを確認せず、直接数字キーの入力を読み取っていた。

<br>

そのためPauseManager側で以下の処理をすべて行っても、Core切り替えだけは別途遮断されなかった。

* プレイヤーコントローラー入力の無効化
* `Player` Action Mapから`UI` Action Mapへの切り替え
* `Time.timeScale = 0`

<br>

これを解決するには、`CoreManager`側でPause状態や共通の入力ロック状態を確認するよう変更するか、Core切り替え入力そのものをInput System Actionへ統合する必要があった。

しかし、これは単純なPause UIの修正ではなく、**Coreシステムの入力処理方式まで変更する必要がある問題** であった。

そのため今週は、ほかのチームメンバーが担当していたCoreシステムを勝手に変更せず、原因と解決方針だけを確認した状態で残した。

単純に「Pause中にCoreが切り替わるバグがある」というだけではなく、**異なる入力方式が一つのプロジェクト内に混在している場合、Pauseのようなグローバル状態の制御が難しくなることを確認した事例** であった。

<br>

## Shader GraphからHLSLベースのShaderへ移行する

Shader Graphベースの汎用ShaderでUI Maskの問題が発生したため、Pause背景用ShaderはHLSLベースの`Shader_Background.shader`として作り直した。

<br>

Shaderには以下のようなプロパティを用意した。

```hlsl
_TintColor("TintColor", Color) = (1, 1, 1, 1)
_Opacity("Opacity", Range(0, 1)) = 1
_Progress("Progress", Range(0, 1)) = 1
_PixelCount("PixelCount", Range(1, 1024)) = 128
_GlowIntensity("GlowIntensity", Range(0, 5)) = 1
_ScanSpeed("ScanSpeed", Range(-5, 5)) = 1
_NoiseStrength("NoiseStrength", Range(0, 1)) = 0.2
_DistortionStrength("DistortionStrength", Range(0, 0.1)) = 0
```

これらの値によって、一つのMaterial内で以下の表現を調整できるようにした。

* UIの色調
* 透明度
* 左右方向の進行度
* ピクセル化の程度
* Glowの強度
* Scanの速度
* Noiseの強度
* Distortionの強度

<br>

Shader Graphで問題になったUI Maskとの互換性に対応するため、Stencil関連のプロパティも直接追加した。

```hlsl
_Stencil("Stencil Ref", Float) = 0
_StencilComp("Stencil Comp", Float) = 8
_StencilOp("Stencil Op", Float) = 0
_StencilReadMask("Stencil Read Mask", Float) = 255
_StencilWriteMask("Stencil Write Mask", Float) = 255
_ColorMask("Color Mask", Float) = 15
```

最初に作ったShader Graphの構造へ固執するのではなく、実際のUIで必要であったMaskやStencil処理を直接扱えるよう、HLSLベースへ方向を変更したのである。

今回の作業を通して、**実装しやすい方法と、実際の要求を満たせる方法が必ずしも同じではないということ** を改めて感じることができた。

## Pause中でもShaderを動かす

Pause状態では`Time.timeScale`が`0`になる。

しかしPause画面のNoise、Scan、Distortionエフェクトまで一緒に停止してしまうと、画面全体が単純な静止画像のように見えてしまう。

今回のPause画面は、ゲームそのものは停止していてもインターフェースだけは動き続ける、一種のシステム画面のように見せたいと考えた。

<br>

そのため、Shaderで使用する時間値をゲーム時間から分離する必要があった。

そこで、`Time.unscaledTime`をグローバルShader値として渡す`DontStopShader`を追加した。

```csharp
private void UpdateTimeParams()
{
    float t = Time.unscaledTime;

    Shader.SetGlobalVector("_UnscaledTimeParams", new Vector4(t * xScale, t * yScale, t * zScale, t * wScale));
}
```

`Time.unscaledTime`は`Time.timeScale`の影響を受けない。

そのためゲーム時間が停止していても`_UnscaledTimeParams`は増加し続け、Pause背景Shaderのアニメーションを維持できる。

<br>

Shader側ではUnity標準のTime Parameterではなく、渡されたUnscaled Timeを使用するようにした。

```hlsl
float4 _UnscaledTimeParams;
```

これによって、**ゲームプレイ自体は完全に停止していても、Pause画面のScanとNoiseは動き続ける状態** を作ることができた。

<br>

**[キャプチャ7を挿入 — Pause中でも動くScanまたはNoiseエフェクト]**

<br>

> `Time.timeScale`が`0`のPause状態でもUI Shaderが動くよう、`Time.unscaledTime`をグローバルShader値として渡した。

この機能は静止画像よりも、2〜3秒程度のGIFや短い動画で見せる方がはるかに分かりやすいと思う。

## マウス位置に反応するPause背景

Pause画面では、マウスを動かした際に背景表現も一緒に変化するよう`PauseMouseController`を追加した。

まずPause Panelを基準として、マウスのローカル座標を計算した。

```csharp
RectTransformUtility.ScreenPointToLocalPointInRectangle(panelRect, Input.mousePosition, cam, out Vector2 localPoint);

Rect rect = panelRect.rect;

float mouseX = Mathf.InverseLerp(rect.xMin, rect.xMax, localPoint.x);
mouseX = Mathf.Clamp01(mouseX);
```

マウスのX座標を`0~1`の範囲へ正規化した後、これを左右方向を示す値へ変換した。

```csharp
float signed = (0.5f - mouseX) * 2f;
float amplified = Mathf.Clamp(signed * amplify, -1f, 1f);
float target = center + amplified * moveRange;
```

マウスが画面中央にある場合は基準値である`center`を使用し、左右へ移動するほど`moveRange`の範囲内で目標値が変化するようにした。

<br>

値が急激に変化しないよう`Lerp()`を使い、滑らかに移動させた。

この処理でもPause状態の影響を受けないよう、`Time.unscaledDeltaTime`を使用した。

```csharp
float t = Mathf.Clamp01(lerpSpeed * Time.unscaledDeltaTime);
progress = Mathf.Lerp(progress, target, t);
```

計算した値はMaterialとグローバルShader変数の両方へ渡した。

```csharp
materialInstance.SetFloat("_Progress", progress);
Shader.SetGlobalFloat("_GlobalProgress", progress);
```

全体の流れを整理すると、以下の通りである。

**マウスを左右へ移動**<br>
→ **Pause Panel基準のローカル座標を計算**<br>
→ **X座標を`0~1`へ正規化**<br>
→ **目標Progressを計算**<br>
→ **Unscaled Delta Timeを使って滑らかに補間**<br>
→ **Materialの`_Progress`を変更**<br>
→ **Pause背景表現が変化**

<br>

この機能によって、Pause画面は単純に動く背景からさらに一歩進み、**プレイヤーのマウス操作に反応するインターフェース** となった。

<br>

**[キャプチャ8を挿入 — マウスの左・中央・右位置によるPause背景の比較]**

<br>

> Pause画面でマウスを左右へ動かすとShaderの`_Progress`値が変化し、それに応じて背景表現も動的に変化する。

この機能についても、静止した比較画像よりGIFで見せる方が実際の感覚を伝えるには適していると思う。
