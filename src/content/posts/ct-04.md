**개발 기간:** 2026.07.20 ~ 2026.07.26<br>
**담당 역할:** HP·Heat·Core 인터페이스 리메이크 및 Skill UI 추가

<br>

2주차에는 기존 Heat·Core HUD에 HP UI를 추가하고, HP 감소 파티클과 Low HP 경고를 구현했다. 또한 HP·Heat·Core UI를 하나의 HUD 프리팹으로 정리하면서, 실제 게임에서 재사용할 수 있는 기본적인 인터페이스 구조를 만들었다.

3주차에는 여기서 한 단계 더 나아가, 기능 위주로 구성되어 있던 HUD를 **『ERROR-CODE-H』의 사이버펑크 분위기에 어울리는 디자인으로 발전시키는 작업** 을 맡았다.

<br>

이번 주의 주요 목표는 다음과 같았다.

* Heat 게이지 디자인 리메이크
* High Heat 및 OverHeat 상태 연출 추가
* Heat 게이지 전용 Shader Graph 제작
* HP 배경 이미지 가독성 개선
* HUD 폰트를 픽셀 스타일로 변경
* Core 옆에 Skill 아이콘 추가
* Skill 사용 시 UI 피드백 추가
* 2주차에 미뤄두었던 사망 연출 구현
* HUD 프리팹 구조 정리

<br>

다만 모든 UI를 한 번에 완전히 리메이크하기에는 작업량이 많았다.

따라서 이번 주에는 **Heat UI, Skill UI, 사망 연출** 을 중심으로 작업하고, HP와 Core UI는 기존 기능 구조를 유지하면서 일부 디자인만 개선했다. 전체적인 리메이크는 이후 작업으로 남겨두었다.

## 기능 중심 HUD에서 사이버펑크 HUD로

1~2주차의 가장 중요한 목표는 Heat, Core, HP 정보가 실제 게임 시스템과 정상적으로 연결되는지를 확인하는 것이었다.

덕분에 HUD는 필요한 정보를 표시하는 기능 자체는 갖추고 있었지만, 아직 『ERROR-CODE-H』의 어두운 SF 세계관이나 사이버펑크 분위기를 충분히 보여주지는 못하고 있었다.

<br>

3주차에는 기존 기능 구조를 유지하면서 시각적인 방향을 다음과 같이 변경했다.

* 직선적이고 기계적인 프레임 사용
* 어두운 배경에서 눈에 띄는 높은 색상 대비
* 일반 상태와 위험 상태의 명확한 색상 구분
* 숫자와 상태 정보가 시스템 메시지처럼 보이는 형태
* 기본 폰트를 픽셀 스타일 폰트로 교체
* HP, Heat, Core, Skill UI의 시각적 언어 통일

<br>

즉, 기존 코드를 전부 새로 만드는 것이 아니라 **이미 구현되어 있는 데이터 연결 구조는 유지하고, 그 위의 이미지·폰트·색상·상태 연출을 교체하는 방식** 으로 작업했다.

<br>

## Heat 게이지 디자인 리메이크

이번 주 작업에서 가장 많은 비중을 차지한 것은 Heat 게이지의 리메이크였다.

Heat는 플레이어의 공격과 Core 전환에 영향을 받는 핵심 전투 자원이다.

따라서 단순히 현재 수치를 보여주는 것뿐 아니라, Heat가 위험한 수준까지 올라갔을 때 플레이어가 숫자를 직접 읽지 않아도 이를 바로 알아차릴 수 있어야 했다.

<br>

이를 위해 Heat UI는 크게 세 가지 상태를 구분하도록 구성했다.

* 일반 Heat 상태
* High Heat 상태
* OverHeat 상태

<br>

각 상태를 판단하기 위한 기본 기준값은 `UIManager`에서 설정했다.

```csharp
[Header("UI Conditions")]
[SerializeField] private float lowHPThreshold = 0.2f;
[SerializeField] private float highHeatThreshold = 0.8f;
[SerializeField] private float overHeatThreshold = 0.999f;
```

현재 Heat가 최대 Heat의 80% 이상이면 High Heat, 거의 100%에 도달하면 OverHeat 상태로 판단한다.

<br>

Heat 값이 변경될 때마다 현재 비율을 계산하고, 그 결과를 `HeatDrawer`에 전달하도록 했다.

```csharp
private void HandleHeatChanged(float currentHeat, float maxHeat)
{
    bool isHighHeat = currentHeat / maxHeat >= highHeatThreshold;
    bool isOverHeat = currentHeat / maxHeat >= overHeatThreshold;

    _heatDrawer.SetHeat(currentHeat, isHighHeat);
    _heatDrawer.SetOverHeat(isOverHeat);
}
```

현재 Heat 수치와 High Heat 여부, OverHeat 여부를 각각 전달함으로써, **게이지의 채움 정도와 위험 상태의 시각 연출을 서로 분리해서 처리** 할 수 있도록 구성했다.

<br>

**[캡처 2 삽입 — Normal, High Heat, OverHeat 상태 비교]**

<br>

> Heat 상태에 따라 HUD의 색상과 연출이 달라진다. 기본 상태에서는 일반 색상을 사용하고, Heat가 80% 이상이면 경고 색상으로 전환된다. OverHeat 상태에서는 점멸 효과를 추가해 위험 상태를 더욱 강조했다.

## Heat 게이지 전용 Shader Graph 제작

기존 Heat 게이지는 Unity UI 이미지의 `fillAmount`를 이용해 단순하게 채움 정도를 표현했다.

하지만 새롭게 디자인한 Heat 게이지는 기울어진 프레임과 Fill 이미지를 사용했기 때문에, 기존의 단순한 이미지 채움 방식으로는 원하는 형태를 만들기 어려웠다.

<br>

그래서 Heat 게이지 전용 `HeatBarShader.shadergraph`와 `HeatBarMaterial`을 새롭게 제작했다.

전용 셰이더에서는 다음과 같은 값을 사용했다.

* `_MainTex`: Heat Fill 이미지
* `_Fill`: 현재 Heat의 채움 비율
* `_Skew`: 게이지의 기울기 조정
* `_Softness`: Fill 경계의 부드러움 조정

<br>

Heat UI에서 사용하는 머티리얼은 각 UI 인스턴스가 독립적인 값을 사용할 수 있도록 복제해서 사용했다.

```csharp
private Material materialInstance;

private void Awake()
{
    if (heatFill == null)
        return;

    materialInstance = Instantiate(heatFill.material);
    heatFill.material = materialInstance;
}
```

공유 머티리얼의 `_Fill` 값을 직접 수정하면 같은 머티리얼을 사용하는 다른 UI까지 동시에 영향을 받을 수 있다.

이를 방지하기 위해 `Instantiate()`를 이용해 별도의 머티리얼 인스턴스를 생성하고, 현재 Heat UI에서만 해당 값을 변경하도록 했다.

<br>

현재 Heat 값은 셰이더의 `_Fill` 속성으로 전달했다.

```csharp
public void SetHeat(float current, bool isHighHeat)
{
    current = Mathf.Clamp(current, 0f, 100f);

    if (materialInstance != null)
        materialInstance.SetFloat("_Fill", current / 100f);

    if (!isOverHeat)
        heatFill.color = isHighHeat ? warningColor : normalColor;

    if (heatText != null)
        heatText.text = $"HEAT_{current:0}%";
}
```

Heat 값은 `0~100` 사이로 제한한 뒤, 100으로 나누어 셰이더에서 사용할 수 있는 `0~1` 범위의 값으로 변환했다.

텍스트도 기존의 단순한 `50%` 표기에서 `HEAT_50%` 형식으로 변경했다.

이는 HUD가 일반적인 상태창보다는 **게임 세계 안의 시스템 인터페이스처럼 보이도록 하기 위한 디자인 선택** 이었다.

<br>

High Heat 상태에서는 Fill의 색상을 일반 색상에서 경고 색상으로 바꾸었다.

다만 OverHeat 상태에서는 별도의 점멸 코루틴이 색상을 제어하기 때문에, `SetHeat()`에서 해당 색상을 다시 덮어쓰지 않도록 `isOverHeat` 조건을 추가했다.

<br>

<br>

> 기울어진 Heat 게이지 디자인에 맞춰 전용 Shader Graph를 제작했다. 코드에서 현재 Heat 비율을 `_Fill` 값으로 전달해 게이지가 실시간으로 채워지도록 구성했다.

## High Heat와 OverHeat 시각 효과

High Heat 상태에서는 게이지가 경고 색상으로 변화하고, OverHeat 상태에서는 Heat Fill이 반복적으로 점멸하도록 만들었다.

```csharp
public void SetOverHeat(bool active)
{
    if (isOverHeat == active)
        return;

    isOverHeat = active;

    if (active)
    {
        blinkRoutine = StartCoroutine(OverHeatBlink());
    }
    else
    {
        if (blinkRoutine != null)
        {
            StopCoroutine(blinkRoutine);
            blinkRoutine = null;
        }

        heatFill.color = normalColor;
    }
}
```

이미 OverHeat 상태라면 동일한 코루틴이 다시 실행되지 않도록 현재 상태를 먼저 비교했다.

OverHeat 상태에서 벗어나면 실행 중인 점멸 코루틴을 중지하고, Heat Fill의 색상을 다시 기본 상태로 돌려놓았다.

<br>

점멸 패턴은 2주차에 구현했던 Low HP 경고와 비슷하게, 짧은 점멸과 대기 시간을 조합하는 형태로 만들었다.

```csharp
IEnumerator OverHeatBlink()
{
    while (true)
    {
        yield return Blink(0.16f);
        yield return new WaitForSeconds(0.6f);

        yield return Blink(0.16f);
        yield return new WaitForSeconds(0.16f);
    }
}
```

이렇게 일반 Heat, High Heat, OverHeat를 각각 시각적으로 구분함으로써, 플레이어가 Heat 숫자를 계속 확인하지 않아도 **현재 위험도가 어느 정도인지 색상과 점멸만으로 파악할 수 있도록** 만들었다.

## HP 배경 이미지와 폰트 개선

HP UI는 전체 구조를 새롭게 만드는 대신, 2주차에 구현해둔 HP Bar와 HP 감소 파티클 구조를 유지하면서 가독성을 개선하는 방향으로 작업했다.

기존 HP 배경 이미지를 수정해 HP Fill과 텍스트가 보다 잘 보이도록 만들었고, 기본 폰트를 픽셀 스타일의 `PixelOperatorSC-Bold`로 교체했다.

<br>

폰트 변경은 HP UI만을 위한 작업이 아니라, HUD 전체의 시각적인 인상을 통일하기 위한 작업이었다.

* HP 수치
* Heat 수치
* Core 이름
* Skill 키 표시
* 사망 화면 텍스트

<br>

이러한 텍스트 요소에 동일한 픽셀 스타일을 적용하여, HUD가 게임 화면 위에 별도로 얹힌 일반적인 UI처럼 보이지 않고 『ERROR-CODE-H』 세계관 속의 기계식 인터페이스처럼 느껴지도록 했다.

다만 HP와 Core UI 전체를 완전히 새로 디자인하는 작업은 예상보다 작업량이 많았다.

따라서 이번 주에는 배경과 폰트, 전체 HUD 배치를 먼저 개선하고, 세부적인 리메이크는 이후 작업으로 남겨두었다.

<br>

## Core 옆에 Skill UI 추가

이번 주에는 기존 Core UI 옆에 현재 사용할 수 있는 Skill을 표시하는 기능도 추가했다.

HUD 프리팹 안에 `Skill_UI` 그룹을 만들고, 세 개의 Skill 슬롯을 배치했다.

<br>

각 슬롯은 다음 요소를 가지고 있다.

* Skill 키 또는 이름을 표시하는 텍스트
* Skill 아이콘 이미지

<br>

초기 `SkillDrawer`에는 세 개의 슬롯을 표시하기 위한 참조만 준비했다.

```csharp
[System.Serializable]
public class SkillSlotUI
{
    public TMP_Text skillText;
    public Image skillImage;
}

[SerializeField] private SkillSlotUI[] skillSlots;
```

처음 Skill UI를 추가했을 당시에는 실제 스킬 관련 플레이어 코드가 아직 완성되지 않은 상태였기 때문에, 실제 사용 이벤트와 바로 연결할 수는 없었다.

<br>

당시 작업 기록에도 다음과 같이 남겼다.

> 스킬 아이콘과 스킬 관련 베이스 코드를 추가했습니다. 아직 작동하지 않으며, 스킬 관련 플레이어 코드가 완성되면 그 후에 연결하겠습니다.

<br>

따라서 7월 23일의 첫 구현에서는 아이콘, 슬롯, 기본적인 UI 구조부터 먼저 제작했다.

이후 Skill 시스템에서 사용할 수 있는 데이터와 이벤트가 준비되면 실제 동작을 연결하는 방식으로 작업을 나눈 것이다.

## Sword Core Skill과 UI 연결

7월 23일 오후에는 팀원이 Sword Core의 두 가지 Skill을 추가했다.

* `UpperSlash`
* `DashSlash`

<br>

이제 실제 Skill 사용을 UI에 전달할 수 있었기 때문에, `SwordCoreSkill`에 Skill 종류와 이벤트를 추가했다.

```csharp
public enum SkillType
{
    UpperSlash,
    DashSlash
}

public event Action<SkillType> OnSkillUsed;
```

각 Skill이 실제로 시작되는 시점에 `OnSkillUsed` 이벤트가 발생하도록 구성했다.

```csharp
public void TryStartUpperSlash()
{
    if (CanStartUpperSlash())
    {
        upperSlashReadyTime = Time.time + upperSlashCooldown;
        heatManager?.AddHeat(upperSlashHeat);
        OnSkillUsed?.Invoke(SkillType.UpperSlash);
        StartCoroutine(UpperSlashRoutine());
    }
}
```

`DashSlash`에도 동일한 방식으로 이벤트를 추가했다.

<br>

여기서 중요한 점은 Skill 키가 단순히 입력되었을 때 이벤트가 발생하는 것이 아니라, **쿨타임 등의 실행 조건을 통과하고 실제 Skill이 시작되는 시점에 이벤트가 발생한다는 점** 이었다.

따라서 Skill이 실제로 실행되지 않았다면 UI 효과 역시 발생하지 않는다.

팀원이 담당하던 Skill 스크립트를 수정한 부분에는 UI 연결을 위해 추가한 코드라는 주석을 남겼고, 디스코드에도 어떤 파일을 수정했는지 따로 공유했다.

## SkillRefManager로 게임 로직과 UI 사이 연결하기

Sword Core의 `SkillType`을 UI에서 그대로 사용하면, UI가 특정 Core의 내부 구현 구조에 직접 의존하게 된다.

이를 조금이라도 줄이기 위해 `SkillRefManager`라는 중간 연결 클래스를 만들었다.

```csharp
public enum SkillType
{
    Skill1,
    Skill2,
    Skill3
}

public event Action<SkillType> OnSkillUsed;
```

`SkillRefManager`는 Sword Core에서 발생한 Skill 이벤트를 받아, HUD가 사용하는 공통 Skill 슬롯 번호로 변환한다.

```csharp
private void HandleSkillUsed(SwordCoreSkill.SkillType skill)
{
    switch (skill)
    {
        case SwordCoreSkill.SkillType.UpperSlash:
            OnSkillUsed?.Invoke(SkillType.Skill1);
            break;

        case SwordCoreSkill.SkillType.DashSlash:
            OnSkillUsed?.Invoke(SkillType.Skill2);
            break;
    }
}
```

게임 로직의 `UpperSlash`는 UI의 첫 번째 슬롯으로, `DashSlash`는 두 번째 슬롯으로 변환했다.

<br>

전체 흐름을 정리하면 다음과 같다.

**Sword Core Skill 실행**<br>
→ **`SwordCoreSkill.OnSkillUsed` 발생**<br>
→ **`SkillRefManager`가 Skill 종류 수신**<br>
→ **UI용 `Skill1` 또는 `Skill2`로 변환**<br>
→ **`SkillRefManager.OnSkillUsed` 발생**<br>
→ **`UIManager`가 이벤트 수신**<br>
→ **`SkillDrawer`에서 해당 아이콘 애니메이션 실행**

<br>

`UIManager`는 `SkillRefManager`의 이벤트를 구독하도록 했다.

```csharp
private void OnEnable()
{
    if (_skillRefManager != null)
        _skillRefManager.OnSkillUsed += HandleSkillUsed;
}

private void OnDisable()
{
    if (_skillRefManager != null)
        _skillRefManager.OnSkillUsed -= HandleSkillUsed;
}
```

Skill 이벤트를 받으면 해당 슬롯 정보를 `SkillDrawer`로 전달한다.

```csharp
private void HandleSkillUsed(SkillRefManager.SkillType skill)
{
    _skillDrawer.SetSkill(skill);
}
```

이를 통해 실제 공격 로직과 UI 애니메이션을 직접 연결하지 않고, 중간 계층을 통해 서로 분리할 수 있었다.

## Skill 사용 시 아이콘 확대 효과

Skill 입력이 실제로 처리되었는지를 플레이어가 즉시 확인할 수 있도록, Skill을 사용하면 해당 아이콘이 잠시 커졌다가 원래 크기로 돌아오는 효과를 추가했다.

```csharp
[SerializeField] private float popScale = 1.2f;
[SerializeField] private float popDuration = 0.1f;
```

기본 설정에서는 Skill 아이콘이 원래 크기의 1.2배까지 확대되고, 0.1초 동안 커진 뒤 다시 0.1초 동안 원래 크기로 돌아온다.

<br>

Skill 종류를 배열 인덱스로 변환한 뒤, 해당하는 아이콘을 찾아 애니메이션을 실행했다.

```csharp
public void SetSkill(SkillRefManager.SkillType skill)
{
    int index = (int)skill;
    Image image = skillSlots[index].skillImage;

    if (image == null)
        return;

    StartCoroutine(PopSkillIcon(image));
}
```

실제 확대와 축소는 코루틴과 `Vector3.Lerp()`를 이용했다.

```csharp
private IEnumerator PopSkillIcon(Image image)
{
    RectTransform rect = image.rectTransform;

    Vector3 originalScale = rect.localScale;
    Vector3 targetScale = originalScale * popScale;

    float time = 0f;

    while (time < popDuration)
    {
        time += Time.deltaTime;
        rect.localScale = Vector3.Lerp(originalScale, targetScale, time / popDuration);
        yield return null;
    }

    time = 0f;

    while (time < popDuration)
    {
        time += Time.deltaTime;
        rect.localScale = Vector3.Lerp(targetScale, originalScale, time / popDuration);
        yield return null;
    }

    rect.localScale = originalScale;
}
```

Skill을 사용하면 해당 아이콘이 빠르게 확대되었다가 다시 원래 크기로 돌아온다.

이를 통해 별도의 텍스트 메시지를 띄우지 않더라도, Skill 입력이 실제로 처리되었다는 사실을 HUD에서 바로 확인할 수 있게 했다.

<br>

**[캡처 5 삽입 — Skill 사용 전과 아이콘 확대 순간 비교]**

<br>

2주차에는 사망 UI에 사용할 에셋이 아직 제작 중이었기 때문에 사망 연출을 후속 작업으로 남겨두었다.

```csharp
private void HandleHPChanged(int currentHP, int maxHP)
```

사망 UI가 시작되면 기존 HUD를 먼저 숨기고, 반투명한 배경을 활성화한다.

```csharp
public void ShowDeathUI()
{
    if (_hud != null)
        _hud.SetActive(false);

    if (_deathBackground != null)
    {
        _background.color = new Color(69 / 255f, 69 / 255f, 69 / 255f, 0f);

        _deathBackground.SetActive(true);
        StartCoroutine(FadeIn());
    }
}
```

처음에는 배경의 알파값을 `0`으로 두고, 0.5초 동안 점차 불투명해지도록 만들었다.

```csharp
private IEnumerator FadeIn()
{
    Color start = new Color(69 / 255f, 69 / 255f, 69 / 255f, 0f);
    Color end = new Color(69 / 255f, 69 / 255f, 69 / 255f, 186 / 255f);

    float duration = 0.5f;
    float t = 0f;

    while (t < duration)
    {
        t += Time.deltaTime;
        _background.color = Color.Lerp(start, end, t / duration);
        yield return null;
    }

    _background.color = end;
    _deathTextGroup.SetActive(true);

    yield return StartCoroutine(ErrorCodeAnimation());
}
```

배경이 나타난 뒤에는 `ERROR CODE` 뒤에 붙는 알파벳이 빠르게 바뀌는 글리치 연출을 재생한다.

```csharp
for (int i = 0; i < 20; i++)
{

    _deathMainText.text = $"ERROR CODE: {c}";

    yield return new WaitForSeconds(0.03f);
}

yield return new WaitForSeconds(0.5f);

_deathMainText.color = Color.red;
```

무작위 알파벳을 20번 빠르게 표시한 뒤, 마지막에는 붉은색 `ERROR CODE: H`가 나타나도록 했다.

그 아래에는 미리 준비한 다섯 문장 가운데 하나를 무작위로 표시하도록 구성해, 플레이어가 사망할 때마다 완전히 같은 문장만 반복해서 보이지 않도록 했다.

## Heatゲージのデザインリメイク

今週の作業で最も大きな割合を占めたのは、Heatゲージのリメイクであった。

Heatは、プレイヤーの攻撃やCore切り替えによって変化する重要な戦闘リソースである。

そのため、単純に現在値を表示するだけでなく、Heatが危険な水準まで上昇した際には、プレイヤーが数字を直接読まなくてもすぐに気づける必要があった。

<br>

そこでHeat UIでは、大きく三つの状態を区別するよう構成した。

* 通常Heat状態
* High Heat状態
* OverHeat状態

<br>

それぞれの状態を判定する基本的な閾値は`UIManager`で設定した。

```csharp
[Header("UI Conditions")]
[SerializeField] private float lowHPThreshold = 0.2f;
[SerializeField] private float highHeatThreshold = 0.8f;
[SerializeField] private float overHeatThreshold = 0.999f;
```

現在のHeatが最大Heatの80%以上であればHigh Heat、ほぼ100%に達した場合はOverHeat状態であると判定する。

<br>

Heat値が変更されるたびに現在の割合を計算し、その結果を`HeatDrawer`へ渡すようにした。

```csharp
private void HandleHeatChanged(float currentHeat, float maxHeat)
{
    bool isHighHeat = currentHeat / maxHeat >= highHeatThreshold;
    bool isOverHeat = currentHeat / maxHeat >= overHeatThreshold;

    _heatDrawer.SetHeat(currentHeat, isHighHeat);
    _heatDrawer.SetOverHeat(isOverHeat);
}
```

現在のHeat値、High Heatであるかどうか、OverHeatであるかどうかをそれぞれ渡すことで、**ゲージのFill量と危険状態の視覚演出を分離して処理** できるよう構成した。

<br>

**[キャプチャ2を挿入 — Normal、High Heat、OverHeat状態の比較]**

<br>

> Heatの状態によってHUDの色と演出が変化する。通常状態では通常色を使用し、Heatが80%以上になると警告色へ切り替わる。OverHeat状態では点滅エフェクトを追加し、危険状態をさらに強調した。

## Heatゲージ専用Shader Graphの制作

既存のHeatゲージでは、Unity UI Imageの`fillAmount`を利用して単純にFill量を表現していた。

しかし、新しくデザインしたHeatゲージでは傾いたフレームとFill画像を使用したため、従来の単純なImage Fill方式では意図した形を作ることが難しかった。

<br>

そこで、Heatゲージ専用の`HeatBarShader.shadergraph`と`HeatBarMaterial`を新たに制作した。

専用Shaderでは、以下の値を使用した。

* `_MainTex`: Heat Fill画像
* `_Fill`: 現在のHeatのFill割合
* `_Skew`: ゲージの傾きを調整
* `_Softness`: Fill境界の滑らかさを調整

<br>

Heat UIで使用するMaterialは、それぞれのUIインスタンスが独立した値を持てるよう複製して使用した。

```csharp
private Material materialInstance;

private void Awake()
{
    if (heatFill == null)
        return;

    materialInstance = Instantiate(heatFill.material);
    heatFill.material = materialInstance;
}
```

共有Materialの`_Fill`値を直接変更すると、同じMaterialを使用しているほかのUIまで同時に影響を受ける可能性がある。

これを防ぐため、`Instantiate()`を利用して別のMaterialインスタンスを生成し、現在のHeat UIだけでその値を変更するようにした。

<br>

現在のHeat値は、Shaderの`_Fill`プロパティへ渡した。

```csharp
public void SetHeat(float current, bool isHighHeat)
{
    current = Mathf.Clamp(current, 0f, 100f);

    if (materialInstance != null)
        materialInstance.SetFloat("_Fill", current / 100f);

    if (!isOverHeat)
        heatFill.color = isHighHeat ? warningColor : normalColor;

    if (heatText != null)
        heatText.text = $"HEAT_{current:0}%";
}
```

Heat値を`0~100`の範囲に制限した後、100で割ることでShaderで使用できる`0~1`の範囲へ変換した。

テキストも、従来の単純な`50%`という表記から`HEAT_50%`という形式へ変更した。

これはHUDを一般的なステータス画面ではなく、**ゲーム世界内のシステムインターフェースのように見せるためのデザイン上の選択** であった。

<br>

High Heat状態では、Fillの色を通常色から警告色へ変更した。

ただしOverHeat状態では別の点滅コルーチンが色を制御するため、`SetHeat()`からその色を再度上書きしないよう`isOverHeat`条件を追加した。

<br>

<br>

> 傾いたHeatゲージのデザインに合わせて専用Shader Graphを制作した。コードから現在のHeat割合を`_Fill`値として渡し、ゲージがリアルタイムで満たされるよう構成した。

## High HeatとOverHeatの視覚エフェクト

High Heat状態ではゲージが警告色へ変化し、OverHeat状態ではHeat Fillが繰り返し点滅するようにした。

```csharp
public void SetOverHeat(bool active)
{
    if (isOverHeat == active)
        return;

    isOverHeat = active;

    if (active)
    {
        blinkRoutine = StartCoroutine(OverHeatBlink());
    }
    else
    {
        if (blinkRoutine != null)
        {
            StopCoroutine(blinkRoutine);
            blinkRoutine = null;
        }

        heatFill.color = normalColor;
    }
}
```

すでにOverHeat状態であれば、同じコルーチンが再度実行されないよう現在の状態を先に比較した。

OverHeat状態から抜けると、実行中の点滅コルーチンを停止し、Heat Fillの色を通常状態へ戻した。

<br>

点滅パターンは、2週目に実装したLow HP警告と同じように、短い点滅と待機時間を組み合わせる形で作った。

```csharp
IEnumerator OverHeatBlink()
{
    while (true)
    {
        yield return Blink(0.16f);
        yield return new WaitForSeconds(0.6f);

        yield return Blink(0.16f);
        yield return new WaitForSeconds(0.16f);
    }
}
```

このように通常Heat、High Heat、OverHeatをそれぞれ視覚的に区別することで、プレイヤーがHeatの数字を常に確認しなくても、**現在の危険度を色と点滅だけで把握できるように** した。

## Sword Core SkillとUIの接続

7月23日の午後には、チームメンバーがSword Coreの二つのSkillを追加した。

* `UpperSlash`
* `DashSlash`

<br>

これにより実際のSkill使用をUIへ伝えられるようになったため、`SwordCoreSkill`にSkillの種類とイベントを追加した。

```csharp
public enum SkillType
{
    UpperSlash,
    DashSlash
}

public event Action<SkillType> OnSkillUsed;
```

各Skillが実際に開始されるタイミングで、`OnSkillUsed`イベントが発生するよう構成した。

```csharp
public void TryStartUpperSlash()
{
    if (CanStartUpperSlash())
    {
        upperSlashReadyTime = Time.time + upperSlashCooldown;
        heatManager?.AddHeat(upperSlashHeat);
        OnSkillUsed?.Invoke(SkillType.UpperSlash);
        StartCoroutine(UpperSlashRoutine());
    }
}
```

`DashSlash`にも同じ方式でイベントを追加した。

チームメンバーが担当していたSkillスクリプトを修正した部分には、UIとの接続のために追加したコードであることをコメントとして残し、Discordでもどのファイルを修正したのかを別途共有した。

## SkillRefManagerでゲームロジックとUIの間を接続する

Sword Coreの`SkillType`をUIでそのまま使用すると、UIが特定Coreの内部実装構造へ直接依存することになる。

この依存を少しでも減らすため、`SkillRefManager`という中間接続クラスを作った。

```csharp
public enum SkillType
{
    Skill1,
    Skill2,
    Skill3
}

public event Action<SkillType> OnSkillUsed;
```

`SkillRefManager`はSword Coreで発生したSkillイベントを受け取り、HUDで使用する共通のSkillスロット番号へ変換する。

```csharp
private void HandleSkillUsed(SwordCoreSkill.SkillType skill)
{
    switch (skill)
    {
        case SwordCoreSkill.SkillType.UpperSlash:
            OnSkillUsed?.Invoke(SkillType.Skill1);
            break;

        case SwordCoreSkill.SkillType.DashSlash:
            OnSkillUsed?.Invoke(SkillType.Skill2);
            break;
    }
}
```

ゲームロジック側の`UpperSlash`はUIの一つ目のスロットへ、`DashSlash`は二つ目のスロットへ変換した。

<br>

全体の流れを整理すると、以下の通りである。

**Sword Core Skillを実行**<br>
→ **`SwordCoreSkill.OnSkillUsed`が発生**<br>
→ **`SkillRefManager`がSkillの種類を受信**<br>
→ **UI用の`Skill1`または`Skill2`へ変換**<br>
→ **`SkillRefManager.OnSkillUsed`が発生**<br>
→ **`UIManager`がイベントを受信**<br>
→ **`SkillDrawer`で該当アイコンのアニメーションを実行**

<br>

`UIManager`は`SkillRefManager`のイベントを購読するようにした。

```csharp
private void OnEnable()
{
    if (_skillRefManager != null)
        _skillRefManager.OnSkillUsed += HandleSkillUsed;
}

private void OnDisable()
{
    if (_skillRefManager != null)
        _skillRefManager.OnSkillUsed -= HandleSkillUsed;
}
```

Skillイベントを受け取ると、該当するスロット情報を`SkillDrawer`へ渡す。

```csharp
private void HandleSkillUsed(SkillRefManager.SkillType skill)
{
    _skillDrawer.SetSkill(skill);
}
```

これにより、実際の攻撃ロジックとUIアニメーションを直接接続せず、中間層を通して互いに分離できるようにした。

## Skill使用時のアイコン拡大エフェクト

Skill入力が実際に処理されたことをプレイヤーがすぐに確認できるよう、Skillを使用すると該当アイコンが一時的に大きくなり、その後元のサイズへ戻るエフェクトを追加した。

```csharp
[SerializeField] private float popScale = 1.2f;
[SerializeField] private float popDuration = 0.1f;
```

基本設定ではSkillアイコンが元の大きさの1.2倍まで拡大し、0.1秒かけて大きくなった後、再び0.1秒かけて元の大きさへ戻る。

<br>

Skillの種類を配列のインデックスへ変換した後、該当するアイコンを探してアニメーションを実行した。

```csharp
public void SetSkill(SkillRefManager.SkillType skill)
{
    int index = (int)skill;
    Image image = skillSlots[index].skillImage;

    if (image == null)
        return;

    StartCoroutine(PopSkillIcon(image));
}
```

実際の拡大と縮小には、コルーチンと`Vector3.Lerp()`を利用した。

```csharp
private IEnumerator PopSkillIcon(Image image)
{
    RectTransform rect = image.rectTransform;

    Vector3 originalScale = rect.localScale;
    Vector3 targetScale = originalScale * popScale;

    float time = 0f;

    while (time < popDuration)
    {
        time += Time.deltaTime;
        rect.localScale = Vector3.Lerp(originalScale, targetScale, time / popDuration);
        yield return null;
    }

    time = 0f;

    while (time < popDuration)
    {
        time += Time.deltaTime;
        rect.localScale = Vector3.Lerp(targetScale, originalScale, time / popDuration);
        yield return null;
    }

    rect.localScale = originalScale;
}
```

Skillを使用すると該当アイコンが素早く拡大され、その後再び元の大きさへ戻る。

これにより、別のテキストメッセージを表示しなくても、Skill入力が実際に処理されたことをHUD上ですぐに確認できるようにした。

```csharp
private void HandleHPChanged(int currentHP, int maxHP)
{
    _hpDrawer.SetHP(currentHP, maxHP);

    bool isLowHP = (float)currentHP / maxHP <= lowHPThreshold;
    _hpDrawer.SetLowHP(isLowHP);

    if (_playerHealth.IsDead && _deathDrawer != null)

}
```

死亡UIが開始されると、まず既存HUDを非表示にし、半透明の背景を有効化する。

```csharp
public void ShowDeathUI()
{

        _hud.SetActive(false);
```

最初は背景のAlpha値を`0`に設定し、0.5秒かけて徐々に不透明になるようにした。

```csharp
private IEnumerator FadeIn()
{
    Color start = new Color(69 / 255f, 69 / 255f, 69 / 255f, 0f);
    Color end = new Color(69 / 255f, 69 / 255f, 69 / 255f, 186 / 255f);

    float duration = 0.5f;
    float t = 0f;

    while (t < duration)
    {
        t += Time.deltaTime;
        _background.color = Color.Lerp(start, end, t / duration);
        yield return null;
    }

    _background.color = end;
    _deathTextGroup.SetActive(true);

    yield return StartCoroutine(ErrorCodeAnimation());
}
```

背景が表示された後は、`ERROR CODE`の後ろに付くアルファベットが高速で切り替わるグリッチ演出を再生する。

```csharp
for (int i = 0; i < 20; i++)
```
