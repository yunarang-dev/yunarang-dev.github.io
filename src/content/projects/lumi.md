> 誰かの夢を輝かせるために。

<br>

**LUMI:NOUS**は、ゲーム開発を始めたばかりの人から熟練した開発者まで、アイデアを持つ誰もが複雑な開発環境に縛られることなく、自分が作りたいものに集中できるよう支援する**統合ゲーム開発ハブ**です。

<br>

Unity、Git、Blender、IDE、CLI、AIなど、ゲーム開発に必要なさまざまなツールを一つの環境の中でつなぎ、プロジェクトの状態を理解しやすい形に整理し、必要な作業を適切なツールやAIへとつなげることを目指しています。

## ✨ LUMI:NOUSの紹介

ゲームを作るためには、思っている以上に多くの準備が必要です。

ゲームエンジンをインストールし、Gitを設定し、開発ツールを準備し、必要なCLIやパッケージを導入し、プロジェクトごとに異なる環境を整える必要があります。

<br>

ゲーム開発を初めて始める人にとっては、この過程そのものが大きな壁になり得ます。

熟練した開発者だからといって、こうした作業が楽しいとは限りません。新しいMacをセットアップしたり、新しいプロジェクトを始めたり、複数のツールの状態を確認したりする作業は、今でも繰り返し時間を消費します。

<br>

LUMI:NOUSは、ここから始まりました。

ゲームを作るために、ユーザーが開発環境のすべての内部構造を理解する必要はないと考えました。

意味も分からないコマンドをターミナルへコピー＆ペーストしたり、複数のアプリケーションを行き来しながら現在の状態を一つずつ確認したり、AIに毎回ファイルパスやプロジェクト構造を説明したりする代わりに、

**その複雑さをLUMI:NOUSが引き受けること。**

それが、このプロジェクトが目指す最も基本的な方向性です。

### 🌌 一つのゲーム開発空間

LUMI:NOUSは、新しいゲームエンジンやIDEではありません。

UnityにはUnityが最も得意とすることを、BlenderにはBlenderが最も得意とすることを任せ、VS CodeやXcode、Riderもそれぞれの専門領域をそのまま担当します。

LUMI:NOUSはこれらのツールを置き換えるのではなく、離れた場所に存在する開発環境を、一つのプロジェクトを中心につなぎます。

<br>

例えば、一つのUnityプロジェクトを開いたとき、LUMI:NOUSは内部で次のような状態を確認できます。

- 現在のUnityプロジェクトとEditorの状態
- 使用中のRender Pipelineと主要パッケージ
- GitブランチおよびWorking Treeの状態
- プロジェクト内のドキュメント
- Unity Editor Bridgeを通じて取得される状態
- 現在AIへ渡すことのできるProject / Document / Unity Context

<br>

しかし、これらすべての情報をそのままユーザーへ表示することを目標としているわけではありません。

<br>

プロジェクトに問題がなければ、

> **Ready**

<br>

問題がある場合は、

> **Needs Attention**

<br>

そして、ユーザーが行うべきことがある場合は、

> **Fix**

<br>

のように、まず必要な結論から表示します。

<br>

**複雑さはLUMI:NOUSが引き受け、ユーザーは自分が作りたいものに集中できるべきです。**

これは、LUMI:NOUSのインターフェースを設計するうえで最も重要な原則の一つです。

### 🧭 すべての人のための一つのインターフェース

LUMI:NOUSでは、初心者向けモードと熟練者向けモードを別々に用意しません。

ゲーム開発の経験がどれほどあるかに関係なく、すべてのユーザーに対して、本当に必要な情報だけを同じように表示することを目指しています。

<br>

例えば、Gitの内部状態が複数の情報から構成されていたとしても、普段は単純に次のように表示できます。

> **Git — main · 3 changes**

<br>

Unity EditorやBridge、プロジェクトパス、パッケージの状態がすべて正常であれば、

> **Unity — Ready**

とだけ表示します。

<br>

より詳しい情報は、問題を診断するときや、ユーザー自身が確認する必要があるときにだけ表示されます。

<br>

つまり、LUMI:NOUSの目標は多くの情報を見せることではなく、

**多くの情報を理解したうえで、必要なものだけを見せること**です。

### 🛠️ 開発環境の準備から

ゲーム開発を始める前からターミナルを開かなければならない体験も、できる限り減らしたいと考えています。

将来的にはLUMI:NOUSから、ゲーム開発に必要なツールがインストールされているか、その状態が正常かを確認し、必要に応じてGUIから直接準備できるようにする予定です。

<br>

例えば、

- Homebrew
- Git
- Unity Hub
- Unity Editor
- Blender
- Codex CLI

<br>

などの状態をLUMI:NOUSが確認し、必要であればユーザーが複雑なコマンドを直接入力しなくても、インストールやアップデートを進められるよう設計します。

<br>

ただし、利便性のためにユーザーが理解していない任意のコマンドを実行する仕組みを作ることはありません。

LUMI:NOUS内部では、あらかじめ定義されたツールと操作のみを利用できるよう制限し、

**何を実行するのかを明確に把握している処理だけを行うこと**

を原則とします。

### 📊 プロジェクトをひと目で

現在、LUMI:NOUSの基本UIは大きく三つの領域に分けて発展させています。

左側では、現在作業したい領域を選択し、

中央では、その機能の詳細を確認し、

右側では、いつでも現在のプロジェクト全体の状態を簡単に確認できます。

<br>

例えば、右側のProject Summaryには次のような情報だけを簡潔に表示します。

- Project
- Unity
- Git
- Build
- AI

<br>

Gitの詳細を確認したい場合は、左側でGitを選択し、中央のWorkspaceでGit GraphやDiffを確認します。

Unityの詳細情報が必要な場合は、Unity画面へ移動します。

<br>

つまり、

> **左側は、どこで作業するのか、**  

> **中央は、現在の作業の詳細、**  

> **右側は、プロジェクト全体が正常かどうかを示します。**

### 🧠 AIサポーター「LUMI」

LUMIは、LUMI:NOUSの中でユーザーを支援するAIサポーターです。

しかし、LUMI:NOUSそのものを単なるAIチャットアプリケーションにすることを目標としているわけではありません。

<br>

AI機能を一切使用しなくても、プロジェクト管理、ドキュメント、Git、Unityの状態確認、Build & Test、開発環境管理といった主要機能はそのまま利用できるよう設計します。

<br>

AIは、その基盤の上でユーザーが望む作業をより簡単に行えるよう支援します。

<br>

例えば、ドキュメントを読んでいる途中で特定の文章をドラッグして選択し、

> **Ask LUMI:NOUS**

を押すと、その部分をそのままContextとして添付し、LUMIに質問できます。

<br>

ユーザーがファイルパスや行番号を直接説明する必要はありません。

<br>

同様に今後は、

- ドキュメントの特定部分
- Git Diff
- Build Error
- ログ
- Unityの状態

なども、現在の作業のContextとして直接つなげられるよう拡張する予定です。

<br>

LUMI:NOUSは、ユーザーがAIのためにプロジェクトを説明するのではなく、

**今見ているものを選択すれば、LUMI:NOUSが必要な情報を自動的につなげてくれる体験**

を目指しています。

### 🗂️ Local-first Project Indexing

LUMI:NOUSでは、プロジェクトを開くたびにすべての情報を最初から分析し直すことがないよう、プロジェクトの状態をバックグラウンドで整理する**Project Index**を計画しています。

最初にプロジェクトを登録するときに基本的な情報を収集し、その後は変更された部分だけを確認しながら、インデックスを常に最新の状態に保ちます。

<br>

この過程で、ファイルパス、サイズ、Unity GUID、パッケージバージョンなど、明確に確認できる情報は通常のプログラムロジックによって処理します。

<br>

一方で、

- ばらばらな名前の正規化
- 簡単なカテゴリ分類
- タグの整理
- 短い説明文の生成

といった軽量な言語処理が必要な作業には、macOSのオンデバイスAIを活用する方向を検討しています。

<br>

プロジェクトのインデックス作成のために、Codexのような外部AIを継続的に呼び出すことはしません。

日常的なインデックス処理は可能な限りユーザーのMac上で行い、追加のAPIコストを発生させることなく継続的に利用できるようにすることが目標です。

外部AIは、複雑な設計、実装、デバッグ、レビューなど、実際により高度な推論能力が必要な場面でのみ使用します。

### 🔗 複数のツールをつなぐハブ

LUMI:NOUSが最終的に目指しているのは、すべての開発機能を一つのアプリケーションの中に作り直すことではありません。

<br>

例えば、ソースコードを修正する必要がある場合、LUMI:NOUSの中に新しいコードエディタを作るのではなく、

> **Open in VS Code**

または

> **Open in Xcode**

を通じて、ユーザーが使用している専門ツールの適切な位置へ直接移動できるようにします。

<br>

3Dモデルを修正する必要があればBlenderへ、

Unity Sceneを確認する必要があればUnity Editorへ、

ファイルそのものを確認する必要があればFinderへつなぎます。

<br>

LUMI:NOUSは、それぞれの専門ツールを置き換える**Tool Replacement**ではなく、

複数のツールを一つの開発フローへとつなげる**Tool Coordinator**を目指します。

### 🤖 AI Indexing & Orchestration

現在、LUMI:NOUSではOpenAI Codexを中心にAI連携機能を開発しています。

モデルそのものの名前を直接役割として使用するのではなく、作業の性質に応じて論理的なModel Levelを利用する構造を採用しています。

- **L0** — Planning / Final Review
- **L1** — Orchestration
- **L2** — Heavy Implementation
- **L3** — Conversation / General Work

現在は、一般的な会話や作業を担当するL3を中心に実際のRuntimeへ接続しており、今後はL0〜L2まで実際の作業分担や検証構造へと拡張する予定です。

<br>

長期的にはCodex一つだけに依存せず、作業の性質に応じて複数の外部モデルやローカルモデルを利用できる構造を目指しています。

モデルが変わったとしても、ユーザーが同じLUMIを通じて、同じプロジェクトと同じ作業体験を継続できるようにすることが目標です。

### 🔓 Open Source Project

LUMI:NOUSは**Apache License 2.0**に基づくオープンソースプロジェクトです。

ソースコードを公開するだけでなく、プロジェクトの設計や開発過程についても、可能な範囲で公開していきたいと考えています。

誰でもLUMI:NOUSを利用し、変更し、自分に必要な機能を追加できます。

<br>

ユーザーを特定のゲームエンジンやAIサービスに閉じ込めるのではなく、

すでに存在する優れたツールを最大限尊重しながら、それらをより簡単につなげられる環境を作ることを目指します。

<br>

現在までに実装されている主な機能は次の通りです。

- 複数プロジェクトの登録およびActive Project管理

今後は、LUMI:NOUSを単に機能が存在するアプリケーションではなく、実際に毎日使えるゲーム開発ハブへと発展させることを目指しています。

LUMI:NOUSは、まだ開発途中のプロジェクトです。

> **ゲームを作るための複雑さではなく、作りたいものそのものに集中できるように。**

> 누군가의 꿈을 빛낼 수 있도록.

<br>

**LUMI:NOUS**는 게임 개발을 처음 시작하는 사람부터 숙련된 개발자까지, 아이디어를 가진 누구나 복잡한 개발 환경에 얽매이지 않고 자신이 만들고 싶은 것에 집중할 수 있도록 돕는 **통합 게임 개발 허브**입니다.

Unity, Git, Blender, IDE, CLI, AI와 같이 게임 개발에 필요한 여러 도구를 하나의 환경 안에서 연결하고, 프로젝트의 상태를 이해하기 쉬운 형태로 정리하며, 필요한 작업을 적절한 도구와 AI로 이어주는 것을 목표로 합니다.

## ✨ LUMI:NOUS의 소개

게임을 만들기 위해서는 생각보다 많은 준비가 필요합니다.

게임 엔진을 설치하고, Git을 설정하고, 개발 도구를 준비하고, 필요한 CLI와 패키지를 설치하고, 프로젝트마다 다른 환경을 맞춰야 합니다.

처음 게임 개발을 시작하는 사람에게는 이 과정 자체가 하나의 큰 장벽이 될 수 있습니다.

숙련된 개발자라고 해서 이러한 과정이 즐거운 것은 아닙니다. 새로운 Mac을 설정하거나, 새로운 프로젝트를 시작하거나, 여러 도구의 상태를 확인하는 일은 여전히 반복해서 시간을 소비하게 만듭니다.

<br>

LUMI:NOUS는 여기에서 출발했습니다.

사용자가 게임을 만들기 위해 개발 환경의 모든 내부 구조를 이해할 필요는 없다고 생각했습니다.

터미널에 의미도 모르는 명령어를 복사하고 붙여넣거나, 여러 프로그램을 돌아다니며 현재 상태를 하나씩 확인하거나, AI에게 매번 파일 경로와 프로젝트 구조를 설명하는 대신,

**그 복잡함을 LUMI:NOUS가 맡는 것.**

그것이 이 프로젝트가 추구하는 가장 기본적인 방향입니다.

### 🌌 하나의 게임 개발 공간

LUMI:NOUS는 새로운 게임 엔진이나 IDE가 아닙니다.

Unity는 Unity가 가장 잘하는 일을 하고, Blender는 Blender가 가장 잘하는 일을 하며, VS Code나 Xcode, Rider 역시 각각의 전문 영역을 그대로 담당합니다.

LUMI:NOUS는 이 도구들을 대체하는 대신, 서로 떨어져 있는 개발 환경을 하나의 프로젝트를 중심으로 연결합니다.

<br>

예를 들어 하나의 Unity 프로젝트를 열었을 때 LUMI:NOUS는 내부적으로 다음과 같은 상태를 확인할 수 있습니다.

- 현재 Unity 프로젝트와 Editor의 상태
- 사용 중인 Render Pipeline과 주요 패키지
- Git 브랜치 및 Working Tree 상태
- 프로젝트 내 문서
- Unity Editor Bridge를 통해 전달되는 상태
- 현재 AI에 전달할 수 있는 Project / Document / Unity Context

<br>

하지만 이러한 정보를 모두 그대로 사용자에게 보여주는 것을 목표로 하지는 않습니다.

<br>

프로젝트가 정상이라면,

> **Ready**

<br>

문제가 있다면,

> **Needs Attention**

<br>

그리고 사용자가 해야 할 일이 있다면,

> **Fix**

<br>

와 같이 필요한 결론부터 보여줍니다.

<br>

**복잡함은 LUMI:NOUS의 몫이고, 사용자는 자신이 만들고 싶은 것에 집중할 수 있어야 합니다.**

이것이 LUMI:NOUS의 인터페이스를 설계하는 가장 중요한 원칙 중 하나입니다.

### 🧭 모두를 위한 하나의 인터페이스

LUMI:NOUS는 초보자용 모드와 숙련자용 모드를 따로 나누지 않습니다.

게임 개발 경험이 얼마나 있는지와 관계없이, 모든 사용자에게 동일하게 필요한 정보만을 보여주는 것을 목표로 합니다.

<br>

예를 들어 Git의 내부 상태가 여러 정보로 구성되어 있더라도, 평소에는 단순히 다음과 같이 보일 수 있습니다.

> **Git — main · 3 changes**

<br>

Unity Editor와 Bridge, 프로젝트 경로, 패키지 상태가 모두 정상이라면,

> **Unity — Ready**

라고만 표시됩니다.

<br>

더 자세한 정보는 문제를 진단하거나 사용자가 직접 확인할 필요가 있을 때만 드러납니다.

<br>

즉, LUMI:NOUS의 목표는 많은 정보를 보여주는 것이 아니라,

**많은 정보를 이해한 뒤 필요한 것만 보여주는 것**입니다.

### 🛠️ 개발 환경의 준비부터

게임 개발을 시작하기도 전에 터미널부터 열어야 하는 경험 역시 줄이고자 합니다.

장기적으로 LUMI:NOUS에서는 개발에 필요한 도구들의 설치 여부와 상태를 확인하고, 필요한 경우 GUI에서 직접 준비할 수 있도록 할 예정입니다.

<br>

예를 들어,

- Homebrew
- Git
- Unity Hub
- Unity Editor
- Blender
- Codex CLI

<br>

등의 상태를 LUMI:NOUS가 확인하고, 필요한 경우 사용자가 복잡한 명령어를 직접 입력하지 않아도 설치와 업데이트 과정을 진행할 수 있도록 설계합니다.

<br>

다만 편의를 위해 사용자가 알지 못하는 임의의 명령어를 실행하는 구조를 만들지는 않습니다.

LUMI:NOUS 내부에서는 미리 정의된 도구와 동작만을 사용할 수 있도록 제한하고,

**무엇을 실행하는지 명확하게 알고 있는 작업만 수행하는 것**을 원칙으로 합니다.

### 📊 프로젝트를 한눈에

현재 LUMI:NOUS의 기본 UI는 크게 세 영역으로 나누어 발전시키고 있습니다.

왼쪽에서는 현재 작업하고 싶은 영역을 선택하고,

가운데에서는 해당 기능의 상세 내용을 확인하며,

오른쪽에서는 언제나 현재 프로젝트 전체의 상태를 간단하게 확인할 수 있습니다.

<br>

예를 들어 오른쪽 Project Summary에는 다음과 같은 정보만 간략하게 표시됩니다.

- Project
- Unity
- Git
- Build
- AI

<br>

Git의 상세 정보를 확인하고 싶다면 왼쪽에서 Git을 선택해 중앙 Workspace에서 Git Graph나 Diff를 살펴보고,

Unity의 상세 정보가 필요하다면 Unity 화면으로 이동합니다.

<br>

즉,

> **왼쪽은 어디에서 작업할 것인지,**  
> **가운데는 현재 작업의 상세 내용,**  
> **오른쪽은 프로젝트 전체가 괜찮은지를 보여줍니다.**

### 🧠 AI 서포터 「LUMI」

LUMI는 LUMI:NOUS 안에서 사용자를 돕는 AI 서포터입니다.

하지만 LUMI:NOUS 자체가 단순한 AI 채팅 프로그램이 되는 것을 목표로 하지는 않습니다.

<br>

AI 기능을 전부 사용하지 않더라도 프로젝트 관리, 문서, Git, Unity 상태 확인, Build & Test, 개발 환경 관리와 같은 핵심 기능은 그대로 사용할 수 있도록 설계합니다.

<br>

AI는 이러한 기반 위에서 사용자가 원하는 작업을 더 쉽게 수행할 수 있도록 돕습니다.

<br>

예를 들어 문서를 읽던 중 특정 문장을 드래그하여 선택한 뒤,

> **Ask LUMI:NOUS**

를 누르면 해당 부분을 그대로 컨텍스트로 첨부하여 LUMI에게 질문할 수 있습니다.

<br>

사용자는 파일 경로나 줄 번호를 직접 설명할 필요가 없습니다.

<br>

마찬가지로 앞으로는,

- 문서의 특정 부분
- Git Diff
- Build Error
- 로그
- Unity 상태

등도 현재 작업의 Context로 직접 연결할 수 있도록 확장할 예정입니다.

<br>

LUMI:NOUS는 사용자가 AI를 위해 프로젝트를 설명하도록 만드는 것이 아니라,

**현재 보고 있는 것을 선택하면 LUMI:NOUS가 필요한 정보를 알아서 연결하는 경험**을 목표로 합니다.

### 🗂️ Local-first Project Indexing

LUMI:NOUS는 프로젝트를 열 때마다 모든 정보를 처음부터 다시 분석하지 않도록, 프로젝트의 상태를 백그라운드에서 정리하는 **Project Index**를 계획하고 있습니다.

처음 프로젝트를 등록할 때 기본적인 정보를 수집한 뒤, 이후에는 변경된 부분만 확인하여 인덱스를 계속 최신 상태로 유지합니다.

<br>

이 과정에서 파일 경로, 크기, Unity GUID, 패키지 버전과 같이 명확하게 확인할 수 있는 정보는 일반적인 프로그램 로직으로 처리합니다.

<br>

반면,

- 제각각인 이름의 정규화
- 간단한 카테고리 분류
- 태그 정리
- 짧은 설명 생성

처럼 가벼운 언어 처리가 필요한 작업에는 macOS의 온디바이스 AI를 활용하는 방향을 고려하고 있습니다.

<br>

프로젝트 인덱싱을 위해 Codex와 같은 외부 AI를 계속 호출하지 않습니다.

일상적인 인덱싱은 가능한 한 사용자의 Mac 안에서 처리하여, 별도의 API 비용 없이 지속적으로 사용할 수 있도록 하는 것이 목표입니다.

외부 AI는 복잡한 설계, 구현, 디버깅, 리뷰와 같이 실제로 더 강한 추론 능력이 필요한 순간에만 사용합니다.

### 🔗 여러 도구를 연결하는 허브

LUMI:NOUS가 궁극적으로 하고자 하는 일은 모든 개발 기능을 하나의 프로그램 안에 다시 만드는 것이 아닙니다.

<br>

예를 들어 소스 코드를 수정해야 한다면 LUMI:NOUS에 새로운 코드 에디터를 만드는 대신,

> **Open in VS Code**

또는

> **Open in Xcode**

를 통해 사용자가 사용하는 전문 도구의 정확한 위치로 이동하도록 합니다.

<br>

3D 모델을 수정해야 한다면 Blender로,

Unity Scene을 확인해야 한다면 Unity Editor로,

파일 자체를 확인해야 한다면 Finder로 이어집니다.

<br>

LUMI:NOUS는 각각의 전문 도구를 대체하는 **Tool Replacement**가 아니라,

여러 도구를 하나의 개발 흐름으로 이어주는 **Tool Coordinator**를 지향합니다.

### 🤖 AI Indexing & Orchestration

현재 LUMI:NOUS에서는 OpenAI Codex를 중심으로 AI 연동 기능을 개발하고 있습니다.

모델 자체의 이름을 직접 역할로 사용하는 대신, 작업의 성격에 따라 논리적인 Model Level을 사용하는 구조를 적용하고 있습니다.

- **L0** — Planning / Final Review
- **L1** — Orchestration
- **L2** — Heavy Implementation
- **L3** — Conversation / General Work

현재는 일반적인 대화와 작업을 담당하는 L3를 중심으로 실제 런타임에 연결되어 있으며, 이후 L0~L2까지 실제 작업 분배와 검증 구조로 확장할 예정입니다.

<br>

장기적으로는 Codex 하나에만 종속되지 않고, 작업 성격에 따라 여러 외부 모델이나 로컬 모델을 사용할 수 있는 구조를 목표로 합니다.

모델이 바뀌더라도 사용자는 동일한 LUMI를 통해 같은 프로젝트와 같은 작업 경험을 이어갈 수 있도록 하는 것이 목표입니다.

### 🔓 Open Source Project

LUMI:NOUS는 **Apache License 2.0**을 따르는 오픈소스 프로젝트입니다.

소스 코드를 공개하는 것뿐만 아니라, 프로젝트의 설계와 개발 과정 역시 가능한 범위에서 함께 공개하고자 합니다.

누구든 LUMI:NOUS를 사용하고, 수정하고, 자신에게 필요한 기능을 추가할 수 있습니다.

<br>

특정 게임 엔진이나 AI 서비스에 사용자를 가두는 것보다,

이미 존재하는 훌륭한 도구들을 최대한 존중하면서 서로 더 쉽게 연결할 수 있는 환경을 만드는 것을 목표로 합니다.

## 💻 LUMI:NOUS의 현재 개발 상태

LUMI:NOUS는 현재 게임 개발 허브로서 필요한 기반 기능을 우선적으로 구축하고 있습니다.

<br>

현재까지 구현된 주요 기능은 다음과 같습니다.

- 다중 프로젝트 등록 및 Active Project 관리
- Git 상태 읽기
- Markdown 문서 열람·검색 및 제한적인 편집
- Codex App Server 연결
- AI Conversation
- 명시적인 승인(Approval) 경계
- Project Context Binding
- Unity Editor 실행 상태 확인
- Unity Editor Bridge 기반 읽기 전용 상태 수집
- Unity Context의 명시적인 AI 첨부
- L0~L3 Logical Model Routing

<br>

이후에는 LUMI:NOUS를 단순히 기능이 존재하는 프로그램이 아니라, 실제로 매일 사용할 수 있는 게임 개발 허브로 발전시키는 것을 목표로 하고 있습니다.

<br>

현재 구체화하고 있는 주요 기능은 다음과 같습니다.

- Environment Health
- Guided Setup 및 개발 도구 설치·업데이트
- Project Summary
- Git Graph
- Build & Test
- Logs & Diagnostics
- 백그라운드 Project Index
- 문서 및 개발 정보의 Selection Context
- Blender 및 MCP 연동
- L0~L3 AI Orchestration
- 승인 기반 Git / Unity / Blender 제어

<br>

LUMI:NOUS는 아직 개발 중입니다.

기능과 UI, 내부 구조 모두 앞으로 계속 바뀔 수 있습니다.

<br>

하지만 이 프로젝트가 최종적으로 만들고 싶은 경험은 처음부터 같습니다.

> **게임을 만들기 위한 복잡함이 아니라, 만들고 싶은 것 자체에 집중할 수 있도록.**
